### 五步法整体概览

龙虾五步法是将任意复杂任务按"意图识别→能力映射→方案规划→自主执行→反思进化"标准化全流程处理的执行框架，确保每项任务有始有终、可追溯、可复盘。核心设计理念：

```
Step 1 意图识别 → 拆解用户需求，分解子目标，指派子Agent负责人
Step 2 能力映射 → 确定所需技能/Agent/工具组合，模型路由决策
Step 3 方案规划 → 生成执行计划，选择协作模式，预测风险
Step 4 自主执行 → 按计划执行，实时监控，记录每步状态与耗时
Step 5 反思进化 → 结果分析，ECC修正，沉淀经验，MD5去重归档
```

## 三、执行流程

### Step 1: 意图识别

**输入**：用户原始需求 / 定时任务触发信号

**处理**：
- 分析需求的核心目标和约束条件
- 判断任务领域（文件/系统/App/搜索/浏览器/量化/蒸馏）
- 拆解为可独立执行的子目标（最多5个并行业务子目标）
- 明确每个子目标的输入、输出、负责人（子Agent指派）
- 判断是否需要双模型交叉验证（安全等级>=4强制启用）
- 判断是否需要启用Goal模式（预估>10分钟或20+文件操作）

**输出**：<任务拆解方案> 含主目标、子目标列表（含子Agent负责人指派）、安全等级评估、Goal模式判断

### Step 2: 能力映射

**输入**：Step 1任务拆解方案

**处理**（按逐级降级原则匹配）：
```
Sub Agents → Skills → Tools → 生成代码执行
     ↓
  模型路由（根据任务特征选择最优模型）
```

**路由规则**：
| 任务特征 | 模型选择 | 备注 |
|---------|---------|------|
| 安全关键 | Claude Mythos 5 | 强制，不可降级 |
| 设计/多模态 | Claude Fable 5 | — |
| 编码/MCP调用 | DeepSeek V4.1 | — |
| 超长文档(>1M Token) | GPT-5.6 | — |
| 成本敏感 | DeepSeek V4.1 | — |
| 通用/日常 | GPT-5.6 | — |

**领域→Agent映射**：
| 领域 | Agent | 默认模型 |
|------|-------|---------|
| 文件操作/搜索/整理 | file-agent | GPT-5.6 |
| 系统设置/进程/桌面 | computer-agent | DeepSeek V4.1 |
| App操作/安装 | app-agent | GPT-5.6 |
| 深度调研 | search-agent | GPT-5.6 |
| 浏览器交互 | browser | GPT-5.6 |

**输出**：<能力映射方案> 含Agent选择、模型路由决策、工具清单、降级路径

### Step 3: 方案规划

**输入**：Step 2能力映射方案

**处理**：
- **单Agent闭环**：一次dispatch_task完成
- **串行协作**：按阶段顺序派发，前一步完成后再派下一步（2-3个Agent）
- **并行协作**：无依赖的子任务同时派发（2-5个Agent，上限5）
- **双模型验证**：安全关键任务同时派发到两个不同模型，交叉验证结果
- **Goal模式**：启用心跳检测(15s间隔)、检查点序列化、断点续跑路径

**输出**：<执行计划> 含协作模式、派发顺序、并行/串行标记、验证策略

### Step 4: 自主执行

**输入**：Step 3执行计划

**处理**：
- 子Agent内部自主规划执行步骤（主Agent不干预）
- 按拆解清单逐项执行，调用对应子Agent、技能、工作流
- 记录每步执行状态（成功/失败/跳过）、耗时、异常
- 每次dispatch_task完成后验收结果
- **失败不盲重试**：分析原因→切换参数/路径/能力层级
- **同类失败上限2次**，超出降级或交还用户
- Goal模式：每15秒心跳信号，超时30秒视为僵死→读取检查点→唤醒续跑
- 双模型验证：两模型结果一致性分数>=0.85才算通过

**输出**：<执行结果> 含每步执行状态（成功/失败/跳过）、失败记录、耗时统计、异常日志、模型使用效果数据

### Step 5: 反思进化

**输入**：Step 4执行结果

**处理（验收四问）**：
1. 执行目标是否完全达成？
2. 是否有真实产物（文件/设置变更）？→ 必须IO验证确认落盘
3. 是否有未完成部分需要其他Agent补全？
4. 是否涉及安全关键场景？如果是，是否经过双模型验证？

**异常修正（ECC框架）**：
- 对异常项调用ECC（Error Correction & Calibration）框架修正
- 文件产出校验（路径、格式、内容完整性）
- 异常项标记并进入修正流程
- 执行优化动作并二次校验

**沉淀动作**：
| 类别 | 动作 | 方式 |
|------|------|------|
| 成功模式 | 归档至知识库（成功模板库） | MD5去重后存储 |
| 失败模式 | 记录错误模式库 | MD5去重后存储 |
| 模型使用效果 | 纳入模型反馈回路 | 统计记录 |
| 新技能/经验 | 写入技能库/记忆库 | MD5去重后存储 |
| 配置更新建议 | 自动提案SOUL/USER/AGENTS更新 | 结构化提案 |
| 任务闭环 | 生成任务闭环报告 | 含完整执行链路追溯 |

> **MD5去重机制**：所有归档内容（成功模式、失败模式、新技能、经验等）写入知识库前执行MD5去重，避免重复存储膨胀。该机制继承自历史 v1.0 版本的归档流程。

**输出**：<反思报告> 含验收结论、ECC修正记录、经验沉淀清单、配置更新建议、任务闭环报告
