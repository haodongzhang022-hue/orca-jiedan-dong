## 0. 一句话结论

> **方案B = 双击本机 `start_gateway_3080.bat` 启动 `gateway_3080.py`，让本机 `127.0.0.1:3081` 网关把 DeepSeek-Harness 的请求「出站」转发到 CNB 云端免费模型，解决 Harness 填 Provider 时的 `Failed to fetch`。**
> **网关一旦起来，`curl http://127.0.0.1:3081/health` 必须返回 JSON（不是 HTML）。**

## 1. 端口约定（两个端口，各归各，别再冲突）

| 端口 | 归属 | 访问地址 | 返回内容 |
|------|------|---------|---------|
| **3080** | DeepSeek-Harness WebUI（`dsh web`） | `http://127.0.0.1:3080` | HTML 网页 |
| **3081** | `gateway_3080.py` 中转网关 | `http://127.0.0.1:3081` | JSON（`/health`、`/v1/models`、`/v1/chat/completions`） |

> ⚠️ 判断"网关起没起来"：看 **3081**。如果 curl `3081/health` 返回 HTML，说明 3081 又被别的程序占了（多半是又把网关错配到 3080 上）。

## 3. 启动步骤（详细到每一步，照着抄）

### 第 0 步：先同步最新代码（确保拿到最新版启动脚本）
```bash
git pull origin main
```
同步后确认 `scripts/gateway_service/start_gateway_3080.bat` 和 `scripts/gateway_service/gateway_3080.py` 存在（都已在同目录，无需再手动放）。

### 第 1 步：确认网关脚本落在 E 盘项目树（固定路径，无需再找）
两个文件已在同目录，无需手动复制。**推荐直接使用 `scripts/gateway_service/start_gateway_3080.bat`**：
> 本地落地位置固定：
> ```
> E:\龙虾AI主控中心\我的AI分身\企业微信群定制接单项目\scripts\gateway_service\
> ├─ start_gateway_3080.bat   ← 双击这个
> └─ gateway_3080.py
> ```
> `start_gateway_3080.bat` 会自动优先在本 `gateway_service\` 同目录查找 `gateway_3080.py`（✅ 规范强制首选），其次回退到仓库源文件备份。
> ❌ **不再扫描 D:\dsh-gateway / D:\dsh 等 D 盘隔离目录**。若缺失，请从仓库同步 `scripts/gateway_service/gateway_3080.py` 放回同目录。

### 第 2 步：启动网关（二选一）

**方式A · 双击（推荐）**
```
右键 scripts/gateway_service/start_gateway_3080.bat → 以管理员身份运行（或直接双击）
```
脚本会自动完成 5 件事：找 gateway_3080.py → 查 Python → 读 CNB_TOKEN → 启动 3081 网关 → 健康检查（未就绪自动重启一次）。

**方式B · 命令行**
```bash
# 注意：必须带 --http --port 3081（3080 留给 Harness WebUI，不能动）
python3 deploy/dsh-desktop/gateway_3080.py --http --port 3081
```
> 若手动命令行启动，需先设置环境变量 `CNB_TOKEN=你的令牌`（脚本方式会自动处理令牌）。

### 第 3 步：验证网关起来了（关键！应返回 JSON 不是 HTML）
```bash
curl http://127.0.0.1:3081/health
# 期望返回：{"ok":true,"mode":"outbound",...}   ← 是 JSON
# 如果返回 HTML 网页 → 说明 3081 被其他程序占用 / 网关没起来
```

可再验证模型列表：
```bash
curl http://127.0.0.1:3081/v1/models
# {"object":"list","data":[{"id":"deepseek-v4-flash",...},{"id":"z-ai/glm-5.2",...}]}
```

### 第 4 步：回 Harness（127.0.0.1:3080）填 Provider
- 新增自定义提供方，配置如下：
  - Provider ID：`cnb-gateway-local`
  - API 地址：`http://127.0.0.1:3081/v1`（**端口是 3081**）
  - API 协议：`openai-completions`
  - API 密钥：`local`（占位即可）
  - 模型：`deepseek-v4-flash`、`z-ai/glm-5.2`
- ⚠️ **操作顺序**：弹窗里**不要点"获取可用模型"** → 直接右下角【创建提供方】保存 → 保存完回到列表页再点"获取可用模型"。
- Provider ID 红色提示是实时校验，**直接忽略**，ID 是合法的。

### 第 5 步：用完后关闭
关掉弹出的 `GW3080-http` 窗口即停止网关。

## 4. 排错对照表（Failed to fetch 快速定位）

| 现象 | 根因 | 解法 |
|------|------|------|
| `3081/health` 返回 HTML | 3081 被别的程序占用 / 网关没起 | 确认网关进程 `GW3080-http` 在跑；`taskkill /f /im python.exe` 后重跑脚本 |
| `3081/health` 404 / 连不上 | 网关根本没启动 | 重新执行第 2 步启动，看弹窗是否报 Python/Token 错 |
| Harness 填 Provider 时 `Failed to fetch` | **本机 3081 网关没启动** | **先起网关（方案B）再回 Harness 创建** |
| Harness 创建 Provider 报 `Resource not found` / 404 | 网关地址缺仓库 slug | 用 `bash scripts/fix_dsh_provider.sh` 一键修复，正确网关为 `https://api.cnb.cool/{组织}/{仓库}/-/ai/chat/completions` |
| curl 提示 401 | `CNB_TOKEN` 未注入/失效 | 在 CNB → 头像 → 个人设置 → 访问令牌 复制后注入环境变量 |
