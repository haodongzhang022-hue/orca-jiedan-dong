## 二、重大发现：链路真相（推翻此前认知）

### 2.1 真实链路

```
Codex CLI / Desktop
  ├─ 环境变量 CODEX_BASE_URL = http://127.0.0.1:18091/v1   ← 优先级高于 config.toml
  ├─ websocket 通道 ws://127.0.0.1:51427/v1/responses
  │     └─ 51427 = teamorouter-desktop.exe（TeamoRouter 桌面客户端，真实网关）
  └─ ws 失败(426) → 回退 HTTP → TeamoRouter Desktop → TeamoRouter 云端
```

### 2.2 四个根因（逐条实测）

| # | 根因 | 证据 |
|---|---|---|
| 1 | **旧 51428 代理只支持 Chat Completions** | `curl 51428/v1/responses` → **404**；`/v1/chat/completions` → 200。而 Codex 用 `wire_api="responses"` → 这就是 glm-5.3-flash-free 一直用不了的真相 |
| 2 | **旧文档结论已过期** | AGENTS.md 记「glm-5.3-flash-free 仅 Chat Completions」。实测 **Responses API 直接 200 通过** → TeamoRouter 已升级，需更新文档 |
| 3 | **CODEX_BASE_URL 覆盖 config.toml** | env 中 `CODEX_BASE_URL=http://127.0.0.1:18091/v1`、`CODEX_MODEL=gemma4:e4b`、`OPENAI_API_KEY=tp-cs3z...`（MiMo key） |
| 4 | **单次请求 token 巨大** | Codex CLI 实测 `tokens used 38,928`（含系统提示+MCP 工具定义）。这就是费用失控的放大器——必须走 0.01 折 |

### 2.3 三模型 Responses 协议实测（全部通过）

| 模型 | 折扣 | Responses API | 结论 |
|---|---|---|---|
| `deepseek-v4-flash-free` | 免费 | ✅ 200 | 主用 |
| `glm-5.3-flash-free` | 0.01折 | ✅ 200 | **推翻旧结论**，可直接用 |
| `deepseek-v4-pro-free` | 免费 | ✅ 200 | 兜底 |
