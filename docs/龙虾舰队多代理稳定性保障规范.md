- **严禁两个服务绑定同一端口**

## 三、模型升级指南（mimo-v2.5 → v3.0）

升级时**只需改代理脚本**，客户端配置零改动：

```
# anthropic_proxy_15721.py 和 codex_tool_proxy.py 中：
UPSTREAM = "token-plan-cn.xiaomimimo.com"  # 如换后端改这里
# 客户端 config.toml 中的 model 名需与新后端支持的模型名一致
```

### 升级步骤
1. 确认新模型 API 兼容 OpenAI Chat Completions 格式
2. 修改代理脚本的 UPSTREAM（如需要）
3. 修改各 config.toml 的 `model = "mimo-v3.0"`（或新模型名）
4. 重启代理：`python anthropic_proxy_15721.py` + `python codex_tool_proxy.py`
5. 测试：`curl http://127.0.0.1:15730/v1/models`

## 四、常见故障与修复

### 故障1：Codex 桌面版 401 Unauthorized
**根因**：wire_api 设为 "responses"，MiMo API 不支持 Responses API 格式  
**修复**：
```toml
# ~/.codex/config.toml
[model_providers.custom]
wire_api = "chat"                    # 必须是 chat，不是 responses
base_url = "http://127.0.0.1:15730/v1"  # 走代理，不直连
```

### 故障2：端口被占用
**诊断**：`netstat -ano | grep LISTENING | grep "15721\|15730\|8642"`  
**修复**：`taskkill /PID <占用进程PID> /F`，然后重启对应服务

### 故障3：代理脚本崩溃
**诊断**：检查代理窗口是否还在，或端口是否还在监听  
**修复**：重新启动代理脚本，或用计划任务自动重启

### 故障4：Orca 打开后 Codex 不稳定
**根因**：Orca 的 codex-runtime-home 配置与全局 ~/.codex 配置冲突  
**修复**：确保 `AppData/Roaming/Orca/codex-runtime-home/home/config.toml` 与 `~/.codex/config.toml` 的 model_provider 和 base_url 一致

## 六、快照规范

- 快照目录：`snapshots/`
- 命名规则：`fleet_snapshot_YYYYMMDD_HHMMSS.tar.gz`
- 大小限制：≤ 20MB
- 内容：所有配置文件（脱敏）+ 代理脚本 + README
- 频率：每次重大配置变更后创建新快照
- 保留：至少保留最近 3 个快照

---

## 七、CC Switch / WorkBuddy 兼容性

- CC Switch 管 Git 仓库路径和 worktree，不涉及 API 代理
- WorkBuddy 使用自己的 Python 环境和 MCP 服务器
- 三套系统**并行运行，互不干扰**
- 如遇端口冲突，检查是否有服务意外绑定了别人的端口
