## 第一部分：先把我的标准写出来（不敷衍）

> 汤嘉锋，你问"先把你的标准写出来"。以下 7 条是我对这份计划**不可妥协的验收标准**。任何一条达不到，这计划就是失败交付。我用这套标准约束自己，也用这套标准让你验收。

### 标准 1：可量化，拒绝"感觉上更聪明了"
每一条能力提升必须给出**可实测的验收指标**（数字/可复现命令），不允许"更智能""体验更好"这种主观词。例：
- ❌ "知识库更智能"
- ✅ "检索命中率：对 100 条历史商单问答，Top-5 命中率 ≥ 80%（可复现脚本跑分）"

### 标准 2：双向闭环，拒绝单向流水线
现状最大短板是**单向同步**（仓库→Obsidian）。我要求四化落地后**双向闭环**：
- Obsidian 编辑/新增笔记 → 反向回流仓库 → 赋能 Agent 执行
- 商单复盘 → 自动萃取 → 更新记忆卡 → 下一单更懂你
- **闭环必须可实测**：改一个 Obsidian 笔记，30 分钟内能回流并被 Agent 读到。

### 标准 3：三份记忆卡是"活资产"，不是摆设
「我的笔记 / 用户画像 / 灵魂」三份记忆卡必须：
1. 落地为仓库内**可版本化的结构化文件**（`docs/记忆卡片/*.md`）
2. Agent 启动时**显式读取**（写进 HERMES/CODEX/CLAUDE 的 system prompt）
3. 每单复盘**自动更新**（纳入萃取管线，非人工手改）

### 标准 4：自动化 = 触发即执行，无人值守
自动化不是"有个脚本在"，而是**定时/事件触发后自动跑通全链路**：
- 定时链：30 分钟同步 + 2 小时对标 + 每日学习 + 每单复盘
- 事件链：商单交付 → 自动萃取 → 自动更新记忆卡 → 自动归档
- **无人值守验收**：连续 24h 无人工介入，所有定时/事件链全部跑通且日志有产出。

### 标准 5：自我进化 = 每单必回灌，知识库自生长
- 每一单商单完成后，**复盘必须自动回灌** SelfLearn + 三记忆卡 + wiki
- 知识库规模**只增不减**（保留版本历史，不覆盖丢失）
- **验收**：连续完成 N 单后，知识库能回答"这单教会了我什么""下单如何避免此坑"

### 标准 6：安全红线，永不妥协
- 全程密钥零明文入库（`git log --all -S "sk-"` 零命中）
- 记忆卡可含用户偏好，但**严禁含密钥/凭证**
- 量化/闲鱼两仓凭证**严禁上云**，仅本机执行

### 标准 7：每项落地都必须"能回滚、能复现"
- 所有脚本带日志 + 断点续传 + 失败降级
- 改动有版本基线（快照），出错能一键回滚
- 每一步都有操作手册/验收清单，可复现执行

> **以上 7 条标准，是我给这份计划的"宪法"。下面所有方案都是围绕这 7 条落地。**

## 第二部分：四化迭代 Obsidian 知识库 —— 架构总览

### 2.1 四化定义（一句话 + 能力域）

| 四化 | 一句话定义 | 落地能力域 |
|---|---|---|
| **智能化** | 知识库能"读懂、检索、关联、生成"，不是静态文件夹 | 语义检索 / 自动摘要 / 自动标签 / 知识关联 / Dataview 仪表盘 |
| **定制化** | 知识库"懂你"，随你的画像、偏好、商单类型自适应 | 用户画像蒸馏 / 定制模板 / 商单类型识别 / 个性化推荐 |
| **全自动化** | 知识从采集→萃取→入库→回灌全自动，无人值守 | 定时触发链 / 事件触发链 / 双向同步 / 无人值守流水线 |
| **自我进化** | 每单闭环自动回灌，知识库自生长、越用越懂 | 商单复盘萃取 / 记忆卡自动更新 / SelfLearn 回灌 / 技能沉淀 |

### 2.2 四化与现状差距（锚定 PR#39 实证）

| 维度 | 现状（实证） | 目标（本计划） |
|---|---|---|
| 智能化 | 有 `wiki/` 知识页但静态、无语义检索 | Dataview 仪表盘 + 自动标签 + 语义检索 |
| 定制化 | ⚠️ **用户画像卡缺失**（评审 P1-1） | 落地三记忆卡，用户画像持续蒸馏 |
| 全自动化 | ⚠️ 单向同步（仓库→Obsidian），缺反向 | **双向闭环**（Obsidian→仓库→Agent） |
| 自我进化 | ⚠️ 知识库反哺断点（P1-1 根因） | 每单自动回灌三记忆卡 + SelfLearn + wiki |

## 第三部分：智能化（Intelligent）

### 3.1 目标与验收
- **目标**：Obsidian 从"文件夹"升级为"可检索、可关联、可生成"的智能知识体。
- **验收指标**：
  - [ ] Dataview 仪表盘已建（`Dashboards/知识库总览.md`），实时统计条目/标签/最近更新
  - [ ] 语义检索可用：对 50 条历史笔记，关键词检索 Top-5 命中率 ≥ 80%
  - [ ] 自动标签：新笔记入库时自动打标签（可复现命令）
  - [ ] 知识关联：wiki 双向链接完整（`[[...]]` 覆盖率 ≥ 60%）

### 3.2 落地组件

**A. Dataview 仪表盘（人看）**
```
Obsidian/Dashboards/
├── 知识库总览.md      → 全库条目/标签/最近更新统计
├── 商单看板.md        → 商单状态机视图（已接单→执行中→待审核→已放行→已归档）
└── 学习进度看板.md    → 对标/萃取进度
```

**B. 语义检索（Agent 用）**
- 基于 `scripts/kb_search.py`：对 Obsidian `.md` 做倒排索引 + 关键词加权检索
- 输出 JSON，供 Agent 调用，返回 Top-5 命中 + 原文片段

**C. 自动标签 + 摘要（萃取管线）**
- 扩展 `auto_knowledge_extract.py`：入库时自动生成 `tags` + 摘要
- YAML frontmatter 规范化：`title/tags/created/updated/source/status`

## 第四部分：定制化（Customized）

### 4.1 目标与验收
- **目标**：知识库"懂你"，随你的画像、偏好、商单类型自适应。
- **验收指标**：
  - [ ] 三记忆卡落地：`docs/记忆卡片/{我的笔记,用户画像,灵魂}.md`
  - [ ] 用户画像持续蒸馏：对话/复盘自动抽取偏好，更新画像卡
  - [ ] Agent 启动显式读取三记忆卡（HERMES/CODEX/CLAUDE system prompt 已声明）
  - [ ] 商单类型识别：新商单自动匹配历史同类单，复用模板与经验

### 4.2 落地组件

**三份记忆卡（结构化，随脚手架版本化）**：
```
docs/记忆卡片/
├── 我的笔记.md    → 我对你的工作流/工具/习惯的"运行笔记"
├── 用户画像.md    → 你的画像：领域/偏好/风格/禁忌/决策习惯
└── 灵魂.md        → 你的核心诉求/价值观/长期目标（AI 对齐锚点）
```

**蒸馏机制（`scripts/distill_user_profile.py`）**：
- 从 `对话记录/` + `docs/技能沉淀/` 自动抽取用户偏好
- 增量更新 `用户画像.md`（保留版本，不覆盖）
- 幂等：重复执行不产生重复条目

## 第五部分：全自动化（Fully Automated）

### 5.1 目标与验收
- **目标**：从采集→萃取→入库→回灌全自动，无人值守。
- **验收指标**：
  - [ ] 定时链跑通：30min 同步 / 2h 对标 / 每日学习 / 每单复盘，连续 24h 无人工介入
  - [ ] 双向闭环：改一个 Obsidian 笔记，30 分钟内回流仓库并被 Agent 读到
  - [ ] 一键部署：`bash scripts/deploy_sihua_kb.sh` 一键拉齐四化组件

### 5.2 定时触发链（Windows 计划任务）

| 任务名 | 周期 | 脚本 | 职责 |
|---|---|---|---|
| `Lobster_AutoSync_30min` | 30 分钟 | `auto_sync_30min.sh` | 双推 + Obsidian 增量同步 + **反向回流** |
| `Lobster_DailyLearn_0900` | 每日 09:00 | `daily_learning_benchmark.sh` | 学习对标 + wiki 入库 |
| `Lobster_Benchmark_2h` | 每 2 小时 | `kb_benchmark_2h.sh` | 对标巡检 + 差距报告 |
| `Lobster_Order_Archive` | 事件触发 | `auto_archive.py` | 商单交付→自动归档→复盘 |

### 5.3 事件触发链（商单闭环）

```
商单交付 → auto_archive.py
   ├─ 生成复盘 → 更新三记忆卡（蒸馏用户偏好）
   ├─ 回灌 SelfLearn_Record.md
   ├─ 归档 docs/技能沉淀/
   └─ 写 echo_wall（群聊痕迹墙，供 Hermes Studio 看）
        ↓
   下一单 Agent 启动时读取 → 更懂你
```

### 5.4 双向闭环（关键修复 P1-1）

```
仓库（CNB=权威源） ──push──▶ 本地 E盘 ──robocopy──▶ G盘/Obsidian
                                        │
Obsidian 编辑/新增 ──反向回流──▶ 仓库 docs/记忆卡片 + wiki
```

`auto_sync_30min.sh` 增加反向回流段：把 Obsidian 的 `wiki/` + `记忆卡片/` 复制回仓库，git 管理冲突。

## 第六部分：自我进化（Self-Evolving）

### 6.1 目标与验收
- **目标**：每单闭环自动回灌，知识库自生长、越用越懂。
- **验收指标**：
  - [ ] 每单商单复盘**自动**回灌 SelfLearn + 三记忆卡 + wiki
  - [ ] 连续完成 5 单后，知识库能回答"这单教会了我什么"
  - [ ] 技能沉淀自动入库：新技能注册进 `skill_registry.json`
  - [ ] 知识库规模只增不减（保留版本历史）

### 6.2 进化管线（`scripts/kb_evolve.py`）

```
每单复盘 → 解析结构
   ├─ 更新用户画像.md（蒸馏新偏好）
   ├─ 更新我的笔记.md（沉淀新工作流/坑）
   ├─ 追加 SelfLearn_Record.md
   ├─ 生成 docs/技能沉淀/<日期>_<商单>_复盘.md
   └─ 更新 wiki 对应领域条目（MOC 链接）
```
