# 13460 代理并发限流（429/403）预案 · v1.0

> 归档日期：2026-08-14
> 触发场景：群聊三引擎（hermes/codex/CLAUDE CODE）同时通过 127.0.0.1:13460 转发 deepseek-v4-flash，出现 429 Too Many Requests / 403 atomgit_session_concurrency_conflict
> 固化位置：本文件 + `scripts/detect_13460_concurrency.cmd`

---

## 一、根因（实测锁定 · 2026-08-14 15:xx）

### 1.1 并发源清单

重启后实测 `netstat -ano | grep 13460` + `Get-CimInstance Win32_Process`：

| 并发源 | PID 举例 | 进程 | 路径 | 说明 |
|--------|---------|------|------|------|
| **AtomCode 代理本体** | 11760 / 11784 | python.exe | `E:\...\AtomCode\scripts\atomcode_proxy.py 13460` | **跑了两份**（一份 hermes-agent venv PID11760，一份 uv cpython-3.11 PID11784）——重复拉起 |
| **Hermes Studio 引擎桥** | 23520 / 22752 / 2744 / 24424 | python.exe | `...\hermes_bridge.py --endpoint tcp://127.0.0.1:52298` 和 `:36361` | Studio 内每个 coding-agent 引擎各自起一个 hermes_bridge.py，**多个引擎同时活跃 = 多条 hermes_bridge 同时打 13460** |
| **Hermes Gateway** | 23336 / 22568 | python.exe | `-m hermes_cli.main gateway run --replace` | 跑了两份（`--replace` 本应单实例，但重启残留导致两份并存） |
| **Studio MCP node** | 23176 / 24484 等 | node.exe | `hermes-studio-mcp.mjs api` | MCP 服务端，并发数随 Studio 房间数增长 |
| **Codex CLI 桌面版** | 11372/16124/12600 等 | Codex.exe / codex.exe | 桌面 Codex 多窗口 | 每个窗口独立连 13460 |

### 1.2 429/403 触发链

1. **AtomCode 代理跑了两份**（PID 11760 + 11784）→ 两份代理同时向 AtomGit 发起 session，AtomGit Lite/Pro 套餐**单会话硬上限**，第二份直接 403 `atomgit_session_concurrency_conflict`
2. **三引擎 hermes_bridge.py 同时活跃** → 同一瞬间三条连接打 13460 → 代理合并向 AtomGit 请求 → AtomGit 免费 Lite 档 QPS/并发硬限 → 429 Too Many Requests
3. **桌面 Codex 多窗口叠加** → 进一步放大并发
4. **Hermes Gateway 两份并存** → 抢端口/抢凭据，偶发 401 token rejected

### 1.3 为什么"重启电脑"会加重

重启后开机自启把代理拉起一次（Hermes_Gateway 计划任务），随后 Hermes Studio 启动又通过 launch.ps1 拉起一次 → **同一代理脚本被两套自启机制各拉一份**，这是 403 的直接来源。`--replace` 只对 gateway 单实例有效，对 atomcode_proxy.py 没有去重。

## 二、下回避免预案（四步）

### Step 1 · 重启后先跑检测脚本（一键）

```cmd
scripts\detect_13460_concurrency.cmd
```

输出：
- AtomCode 代理实例数（>1 即异常）
- Hermes Gateway 实例数（>1 即异常）
- ESTABLISHED 连接数（>3 即并发过高）
- 三引擎 hermes_bridge 活跃数

### Step 2 · 自动去重（脚本内置）

检测脚本发现代理>1 份时，自动 `taskkill /F` 保留 PID 最小的一份，其余杀掉。Gateway 同理。

### Step 3 · 引擎串行化（人工 · 三引擎只留一个活跃窗口）

| 场景 | 正确做法 |
|------|----------|
| 群聊只让 hermes 应答 | Studio 里只开 hermes 房间，codex/CLAUDE CODE 房间暂停（点房间右上角暂停按钮） |
| 需要 codex 执行 | 先让 hermes 把任务卡写完→点名 @codex→hermes 房间暂停→codex 房间激活 |
| 需 CLAUDE 审核 | codex 执行完→codex 房间暂停→CLAUDE CODE 房间激活 |

**铁律：同一时刻只有一个引擎在向 13460 发请求，绝不三引擎同时活跃。**

### Step 4 · 桌面 Codex 单窗口

桌面 Codex.exe 多开窗口每个都连 13460，群聊期间只保留一个 Codex 窗口，其余关闭。
