## 二、风险排查

### 二.1 v2.0 静默安装全流程风险矩阵

| 风险点 | 级别 | 描述 | 缓解方案 |
|--------|------|------|----------|
| GitHub Release 下载失败 | 🟡 | 被墙/限速导致 `Invoke-WebRequest` 超时 | 预置 ghproxy 镜像备用 URL；下载失败写 `need_human_click` |
| `--silent` 参数不兼容 | 🟡 | Hermes Studio 安装包可能不支持静默参数，或使用 `/S` / `/quiet` 不同语法 | 安装前用 `& installer.exe /?` 探测；不支持则降级手动 |
| UAC 提权弹窗 | 🟡 | Windows UAC 可能在静默安装时弹出确认框 | 若 Marvis 进程无管理员权限，安装会阻塞；需先探测权限 |
| 安装路径写死 | 🟢 | 用户指定 `E:\龙虾AI主控中心\我的AI分身`，安装包默认路径可能不同 | 安装命令中显式传 `/D=目标路径` 参数 |
| 磁盘空间不足 | 🟢 | 163.3MB 安装包 + 解压后空间 | 安装前检查 `E:` 剩余空间 > 1GB |
| 已有旧版覆盖 | 🟡 | 已有 Hermes Studio 进程运行中，静默安装可能失败 | 安装前 `taskkill /f /im Hermes*` 强杀旧进程 |

**综合结论**: 🟡 中风险 — 主要不确定性在 `--silent` 参数兼容性和 UAC 提权。建议 Marvis 执行时分三步：①探测安装参数 ②检查权限和空间 ③执行安装。任一步失败写降级标记。

### 二.2 跨域网关桥接 — 环境变量密钥风险

| 风险点 | 级别 | 描述 | 缓解方案 |
|--------|------|------|----------|
| GH_TOKEN 明文写入 config.yaml | 🔴 | `one_click_cnb_gateway.sh` 将 Token 写入配置文件 → git commit 推送到 CNB 仓库 → **Token 泄露到公开/半公开仓库** | 严禁 Token 写入版本控制文件；config.yaml 应引用环境变量 `${GH_TOKEN}` 而非明文 |
| Token 缺失时静默失败 | 🟡 | GH_TOKEN 系统环境变量未设置时，脚本可能写入空值 | 写入前先 `Test-Path env:GH_TOKEN`，空则中止并告警 |
| `.env` vs `config.yaml` 混淆 | 🟡 | PR 同时提到 `.env`（本地）和 `~/.hermes/config.yaml`（应用配置），Token 放哪里可能混淆 | 明确：Token 只走系统环境变量，config.yaml 写 `${GH_TOKEN}` 占位符引用 |
| cnb_sync.bat 误同步配置文件 | 🟡 | 三端同步定时任务可能把含路径/密钥的 config.yaml 推上 CNB | `.gitignore` 加 `config.yaml`；同步脚本跳过 `.hermes/` 目录 |

**综合结论**: 🔴→🟢 已修复 — `one_click_cnb_gateway.sh` 实测使用 `api_key_env: CNB_TOKEN` 环境变量引用，无明文 Token 写入 config.yaml；全仓库提交历史扫描无 ghp_/5Srj 等明文 Token 残留。修复措施：①域标注改为"Windows本机Marvis域专属" ②`set -euo pipefail` 添加兼容回退 ③CRLF→LF行尾统一 ④`--dry-run` 试运行通过。

### 二.3 消息痕迹墙 — 跨域同步断点

PR 描述：
> "本地 Hermes Studio 桌面版文件浏览器直接看到"

**断点分析**：

```
云端容器写入 msgbus/inbox/echo_wall/*.md
           ↓
    git add + git commit + git push
           ↓
         ⚠️ 断点1: 容器销毁前 git push 是否100%成功？失败则痕迹永久丢失
           ↓
    orca-jiedan 仓库 main 分支
           ↓
         ⚠️ 断点2: 本地 Hermes Studio "文件浏览器"如何读取远端仓库文件？
           │ Hermes Studio 桌面版内置的是本地文件浏览器，不是 git 客户端
           │ 若 Hermes Studio 的工作目录恰好是 orca-jiedan 本地 clone
           │ → 需要本地执行 git pull 才能看到新痕迹
           ↓
         🔴 断点3: git pull 由谁触发？
```

**当前状态**: 三端同步定时任务 `龙虾AI_E-G-CNB三端同步` 每30分钟跑 `cnb_sync.bat`，可以拉取云端痕迹文件到本地。但：
1. 30分钟延迟对实时群聊痕迹墙过长
2. 定时任务失败 → 痕迹永久不可见
3. 没有主动推送机制（容器无法通知本机）

**修正建议**：
- 最短路径：本地 Hermes Studio 工作目录直接指向 `orca-jiedan` 本地克隆 → git pull 在 Marvis 定时巡检中拉取（已有 30 分钟）
- 理想路径（非必须本次）：Marvis 监听 CNB Webhook → 云端 push 后立即 git pull
- 接受现状：30分钟延迟可接受（群聊痕迹墙是事后审计，非实时监控）

**综合结论**: 🟡→🟢 已修复 — v2.0 文档已修正为"云端容器文件经30分钟定时git push→本机git pull同步后查看，存在固定同步延迟；非实时直读"，如实标注延迟特性。`cnb_echo_ping.sh` 行尾统一为 LF。

### 二.4 整体跨域通信缺口汇总

| 缺口 | 严重度 | 方向 | 现状 |
|------|--------|------|------|
| Token 跨域泄露 | 🔴 | Windows→CNB | config.yaml 明文 Token git push → 泄露 |
| 云→本机文件同步延迟 | 🟡 | CNB→Windows | 30分钟一次性容器可能等不到下次git pull |
| 域名标注错误 | 🟡 | 双域 | `one_click_cnb_gateway.sh` 标注云端实为本机 |
| 「直接看到」描述不实 | 🟢 | CNB→Windows | 实为 git pull 后看到，非直接 |
