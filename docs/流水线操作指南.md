# 企业微信群定制接单项目 · 流水线操作指南

> 本文档对应 ORCA 三 Agent 舰队工作流：Hermes（大脑/需求拆解）→ Codex（执行/设计产出）→ CloudCode（核查/质量合规成本）。  
> WorkBuddy 负责总线调度、自动生成下游任务卡、汇总交付物到企业微信群文件夹；你只需在企业微信群下发需求或上传截图，最终复制交付物即可。

## 二、三条执行路线

### 路线 1：全自动单订单流水线（推荐常规商单）

**场景**：客户需求清晰、参考图完整、无需二次确认，直接跑通 Hermes → Codex → CloudCode。

**启动步骤**：
1. 在项目根目录启动看板服务（若未启动）：
   ```bash
   cd "E:/龙虾AI主控中心/我的AI分身/企业微信群/定制接单项目/任务看板"
   python -m http.server 8000
   ```
2. 启动 WorkBuddy 自动驾驶守护进程：
   ```bash
   cd "E:/龙虾AI主控中心/我的AI分身/企业微信群定制接单项目"
   python scripts/pipeline_autopilot_daemon.py
   ```
3. 在三个 ORCA 工作树终端分别执行：
   ```bash
   # Hermes 工作树（hermes/brain 分支）
   bash scripts/route_1_auto_pipeline.sh

   # Codex 工作树（codex/executor 分支）
   bash scripts/route_1_auto_pipeline.sh

   # CloudCode 工作树（claude/reviewer 分支）
   bash scripts/route_1_auto_pipeline.sh
   ```

**效果**：
- Hermes 自动认领需求卡，产出 `design_brief.md`。
- WorkBuddy 自动创建 `_Codex_` 任务卡到 `fleet_exchange/incoming/`。
- Codex 自动认领，产出设计方案到 G 盘 `outputs/<task_id>/`。
- WorkBuddy 自动创建 `_CloudCode_` 任务卡。
- CloudCode 自动认领，产出审核报告到 G 盘 `outputs/<task_id>/`。
- WorkBuddy 自动汇总所有结果到 `deliverables/<task_id>/`。

**轮询参数**：30 秒扫描一次，连续 10 分钟无任务自动退出。

---

### 路线 2：前置确认校验模式（需求模糊时使用）

**场景**：客户需求缺少关键信息（尺寸、结构、包装、文字内容），需要你先和客户确认，避免返工。

**启动步骤**：
1. 在 Hermes 工作树执行一次（只处理当前任务，不轮询）：
   ```bash
   bash scripts/route_2_confirm_first.sh
   ```
2. Hermes 产出 `design_brief.md` 后，WorkBuddy 在 `CONFIRM_MODE=true` 下会把 `_Codex_` 任务卡写入 `待确认/` 目录，**不会自动进入 `incoming/`**。
3. 在浏览器看板 `http://localhost:8000` 中查看“待确认任务”。
4. 你和客户确认需求后，放行任务：
   ```bash
   bash scripts/confirm_task.sh <task_id>
   # 示例：
   bash scripts/confirm_task.sh 20260725_232000_0
   ```
5. 三个工作树切回路线 1：
   ```bash
   bash scripts/route_1_auto_pipeline.sh
   ```

---

### 路线 3：无限轮询批量接单模式（群内多单持续涌入）

**场景**：企业微信群内持续来单，需要三 Agent 常驻后台自动排队处理。

**启动步骤**：
1. 在项目根目录启动自动驾驶守护进程：
   ```bash
   cd "E:/龙虾AI主控中心/我的AI分身/企业微信群定制接单项目"
   python scripts/pipeline_autopilot_daemon.py
   ```
2. 在三个工作树终端分别执行：
   ```bash
   bash scripts/route_3_batch_daemon.sh
   ```

**效果**：各 Agent 会**永久轮询** `incoming/`，有新任务立即认领，按 Hermes → Codex → CloudCode 顺序自动接力。按 `Ctrl+C` 或关闭终端停止。

| 日志 | 路径 |
|------|------|

| 舰队操作日志 | `E:/龙虾AI主控中心/我的AI分身/企业微信群定制接单项目/fleet_exchange/logs/ops_YYYYMMDD.log` |
| 看板服务日志 | 启动 http.server 的终端输出 |

### 常见问题

1. **看板 8000 端口无法访问**
   - 确认 http.server 已启动：`curl http://localhost:8000/dashboard_data.json`
   - 检查防火墙是否放行本地 8000 端口。

2. **Agent 没有自动认领任务**
   - 确认任务卡文件名含 `_Hermes_` / `_Codex_` / `_CloudCode_`，或 frontmatter 中 `to:` 字段正确。
   - 确认当前工作树分支正确：`git rev-parse --abbrev-ref HEAD`
   - 确认 `ORCA_AGENT_NAME` 环境变量或脚本参数正确。

3. **G 盘目录无法创建**
   - 检查 `G_DRIVE_ROOT` 是否指向有效盘符和可写目录。
   - 默认路径 `G:/WorkBuddy-Cache/...` 为建议值，若本机策略不允许，请自定义。

4. **下游任务卡在 `待确认/` 不放行**
   - 执行 `bash scripts/confirm_task.sh <task_id>` 放行。

## 八、图像生成：FAL-free 自动降级

### 8.1 设计目标

- **不强制依赖 FAL_KEY**：外部付费 API 降为可选通道，有密钥则优先使用；无密钥时自动走免费方案。
- **永不降到人工复制 Prompt**：任何情况下流水线都在 Agent / 工具内部闭环完成。
- **零成本优先**：优先使用本地 SVG 渲染、WorkBuddy 内置 ImageGen、mimo-bridge / ollama-bridge 等免费算力。

### 8.2 三级自动降级

```
Codex 产出 image_gen_requests.json + SVG 矢量稿
           │
           ▼
┌─────────────────────┐
│ 1. FAL（外部付费API） │ ← 仅当 FAL_KEY 配置时尝试
└─────────────────────┘
           │ 失败/未配置
           ▼
┌─────────────────────┐
│ 2. SVG 本地渲染成PNG │ ← 使用 cairosvg / inkscape / rsvg-convert，免费
└─────────────────────┘
           │ 失败/无SVG
           ▼
┌─────────────────────┐
│ 3. WorkBuddy ImageGen│ ← 写入 pending_workbuddy_image_gen.json，由 WorkBuddy 在线时完成
└─────────────────────┘
           │ 仍失败
           ▼
┌─────────────────────┐
│ 4. Prompt 模板兜底   │ ← 写入 markdown，至少保留 prompt 不丢失
└─────────────────────┘
```

### 8.3 Codex 任务卡要求

Codex 在产出方案时，**必须**同时生成：

1. `outputs/<task_id>/image_gen_requests.json`：每个请求包含 `output_name`、`prompt`、`prompt_cn`、`svg_file`、`size`。
2. 对应方案的 SVG 矢量稿（放在 `outputs/<task_id>/方案X_.../`）。
3. `文生图Prompt集.md`：供人工/其他工具二次使用（但流水线本身不再依赖人工复制）。

### 8.4 自动驾驶中的图像处理

当 Codex 完成并返回结果后，WorkBuddy 自动驾驶会立即调用：

```bash
python scripts/image_generation_adapter.py --task-id <TASK_ID> --mode auto
```

- 若全部图片生成成功，才继续创建 CloudCode 终审任务。
- 若存在 WorkBuddy ImageGen 待处理钩子，会暂缓 CloudCode 任务，并在看板显示 `WAITING_IMAGE_GEN` 状态。
- WorkBuddy 在线生成图片后，将其放入 `completed_workbuddy_images/` 并重新运行 autopilot，即可继续终审。

### 8.5 手动触发图像生成（调试用）

```bash

```

**金羊钥匙扣（20260725_232000_0）**：无 FAL_KEY 场景下，自动完成 SVG 渲染，并叠加 WorkBuddy ImageGen 免费 AI 效果图，最终交付物落盘 `deliverables/20260725_232000_0/`。详见 `outputs/20260725_232000_0/FAL_free_测试报告.md`。

## 九、业务目录归档（定型标准）

接单项目按「定型目录标准」管理，详见 `docs/目录结构标准.md`。核心规则：

1. **两条线严格区分**
   - 群里几十元低价需求、内部训练需求 → `00_模拟演练案例库/`（仅跑通流水线、沉淀技能，**不接真实交易、不对外交付**）。
   - 满足 ¥300 起步、已收定金的真实付费单 → `01_正在执行实单/`。
   - 判定逻辑由 `scripts/business_folders.py` 自动完成：`simulation:true` 或 `real_order_min < 300` → 模拟；`real_order_min >= 300` → 实单。

2. **每个独立需求单独建 `【日期_简述】` 文件夹**，内部标配：
   聊天记录 / 参考原图 / 需求确认文档 / 工程源文件 / 各版本稿件 / 最终交付文件
   （自动驾驶在接单时自动调用 `business_folders.py scaffold` 生成，无需手建。）

3. **归档**：交付完成、尾款结清后，把 `01_正在执行实单/【…】` 移动到 `02_已完结归档实单/<品类>/`：
   ```bash
   python scripts/archive_order.py "【20260725_科技折页画册】" --category 画册排版类
   ```

4. **代码调度层 与 业务素材层 互不影响**：`worktrees/`、`fleet_exchange/`、`scripts/`、`docs/` 顶层不动；业务资料只进 `00/01/02/03` 与 `outputs/` 临时缓存。

> **一键创建骨架**：受管仓库禁止直接写新目录时，在本机运行
> `bash scripts/创建目录结构.sh`（或 `powershell -ExecutionPolicy Bypass -File scripts/创建目录结构.ps1`）即可建好整套结构。
