## 二、三条执行路线

### 路线1：全自动模式（推荐常规商单）

**适用场景**：需求清晰、报价明确、无需二次确认的订单

```bash
bash scripts/route1_fullauto.sh fleet_exchange/incoming/<任务卡文件名>.md
```

**执行流程**：
1. 自动创建 `outputs/<任务ID>/` 目录并归档任务卡
2. 运行 `pipeline_autopilot.py` 推进当前阶段
3. 启动后台守护进程（每30秒自动检查推进后续阶段）

**监控**：
```bash
tail -f logs/route1_daemon_<任务ID>.log
python scripts/pipeline_autopilot.py  # 手动触发一次检查
```

---

### 路线2：前置确认模式（需求模糊时使用）

**适用场景**：客户未明确尺寸/结构/页数等关键参数，需要二次确认

```bash
bash scripts/route2_preconfirm.sh fleet_exchange/incoming/<任务卡文件名>.md
```

**执行流程**：
1. 解析需求卡，提取待确认事项、报价、交付格式
2. 输出确认清单，等待用户与客户确认
3. 确认无误后，加 `--confirm` 参数直接启动流水线：
   ```bash
   bash scripts/route2_preconfirm.sh <任务卡路径> --confirm
   ```

---

### 路线3：自动轮询模式（批量来单场景）

**适用场景**：企业微信群持续涌入大量订单，需要无人值守批量处理

```bash
bash scripts/route3_autopoll.sh [扫描间隔秒] [超时退出秒]
```

**默认参数**：每30秒扫描一次，连续10分钟无任务自动退出

**执行流程**：
1. 持续扫描 `fleet_exchange/incoming/` 目录
2. 发现含 `_Hermes_` 标记或 `to: Hermes` 的新任务自动认领
3. 认领后自动运行流水线处理
4. 处理完继续扫描，直到超时退出

**后台运行**：
```bash
nohup bash scripts/route3_autopoll.sh 30 600 > logs/route3_poll.log 2>&1 &
```

## 三、任务卡规范

### 文件命名规则

```
<时间戳>_<序号>__<AgentTag>_<任务简称>.md
```

- 时间戳格式：`YYYYMMDD_HHMMSS`
- AgentTag 必须为 `_Hermes_`、`_Codex_`、`_CloudCode_` 之一（`fleet_pull.sh` 按此识别）
- 任务简称使用中文，简明扼要

示例：`20260725_232000_0__Hermes_金羊钥匙扣_可旋转金片_高级感.md`

### Frontmatter 必填字段

```yaml
---
task_id: 20260725_232000_0
from: WeCom          # 来源（WeCom / WorkBuddy / 手动）
to: Hermes           # 目标 Agent
priority: high       # high / medium / low
created: 2026-07-25 23:20:00
simulation: false     # true=演练 / false=真实商单
real_order_min: 160   # 真实订单最低报价（元）
---
```

## 六、注意事项

1. **文件名铁律**：任务卡文件名必须含 `_Hermes_` / `_Codex_` / `_CloudCode_`，否则 `fleet_pull.sh` 会跳过
2. **工作树隔离**：不要在主分支执行 Agent 专属操作，必须切到对应工作树
3. **截图归档**：客户参考截图统一存入 `outputs/<任务ID>/客户参考截图.png`
4. **日志留存**：所有流水线操作自动记录到 `logs/` 目录，中断可追溯
5. **磁盘管控**：产出文件统一落地 G 盘（大文件），任务卡/日志等小文件留在 E 盘
