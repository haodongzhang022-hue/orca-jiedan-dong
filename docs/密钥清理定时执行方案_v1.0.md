## 〇、一句话结论（回答"会不会影响正常使用"）

**清理 P0-1 明文密钥【不影响】任何正常功能。** 因为：

1. 那条 `sk-07d448...` 的 DeepSeek 官方 key **运行时根本不是从日志 .md 文件读取的**；
2. 实际调用链是 `Windows 环境变量 DEEPSEEK_API_KEY（setx 已写入注册表，永久生效）→ config.yaml / models.json 用 ${DEEPSEEK_API_KEY} 占位引用 → 代理读环境变量`；
3. 日志 .md 里的明文只是**历史会话存档的历史副本**，任何进程都不读它，删掉/脱敏它不会让 DeepSeek 掉线、不会让 Hermes/Codex/Claude 哑火。

**唯一需要小心的"影响"点**：若要做彻底 git 历史清理（filter-repo 重写），会**改变 commit SHA 并需要 force-push**——这只影响"版本号/克隆/工作树需要重新同步"，**不影响运行功能**。它属于可选深清理，可放在维护窗口人工做。

## 二、清理范围分层（三层，按风险从高到低）

### 层 1：工作区存档脱敏（本方案自动做 · 必做）
- 目标：`对话记录/**/*.md` 及全仓库文本中所有 `sk-` / `ghp_` / `tp-` / `api_key=xxx` 明文 → 替换为 `{{REDACTED:类型}}` 占位符。
- 由定时脚本 `scripts/secret_scan_cleanup.py` 自动完成，保留行结构与可读性。
- **对功能零影响**。

### 层 2：git 历史重写（可选深清理 · 维护窗口人工做）
- 用 `git filter-repo` 从 commit `bfe1343` 起抹掉含密钥的提交/文件内容，改变 SHA，需 force-push。
- **建议**：在"本地双推 + Obsidian 已归档 + 无进行中工作树"的低峰窗口执行；执行前先 `git clone --mirror` 全量备份。
- **对功能零影响**，只影响克隆/工作树需重新同步。

### 层 3：密钥本体轮换（建议人工做 · 安全红线）
- 若该 key 仍有效：到 platform.deepseek.com 直接**吊销并重建**一条新 key，写入环境变量 `DEEPSEEK_API_KEY`（setx），旧 key 作废后即使泄漏也无价值。
- 本脚本不自动吊销（无授权），仅提示。

## 三、定时执行方案（Hermes 侧怎么"定时跑"）

沿用项目已有的「云端出脚本 → Marvis 落 Windows 计划任务」模式，**不新增 schtasks 执行代码**，只把调度参数登记进 `config/autogpt/triggers.yaml`。

### 3.1 新增触发器（已写入 `config/autogpt/triggers.yaml`）

```yaml
AG_Secret_Cleanup:
  cron: "0 2 * * *"
  schedule_human: "每日 02:00"
  workflow: "安全基线"
  desc: "P0-1 密钥定时扫描+自动脱敏（检测 sk-/ghp_/tp-/api_key 明文入库）"
  params:
    action: "redact"
    task_name: "secret_cleanup_scan"
    file_path: "scripts/secret_scan_cleanup.py"
```

### 3.2 脚本用法（Marvis 落计划任务时调用）

```bash
# 每日定时自动执行（推荐，低峰 02:00）：
python scripts/secret_scan_cleanup.py --action redact
#    → 扫描全仓库 + 自动脱敏命中行 + 写 fleet_exchange/results/secret_scan_*.json + 回写 local_job_queue.json

# 只扫描不改写（预演）：
python scripts/secret_scan_cleanup.py --action scan

# 查看最近一次报告：
python scripts/secret_scan_cleanup.py --action report
```

### 3.3 Marvis 落地步骤（本地，一次性部署）

1. `git pull` 拉取本 PR；
2. 把 `AG_Secret_Cleanup` 落成 Windows 计划任务（每日 02:00，运行上述 `redact` 命令）；
3. 首次手动跑一次 `--action redact`，把现存泄漏脱敏 → `git add/commit` → push；
4. 之后每次定时跑，若报告有新增命中 → 复查确认 → commit；
5. 结果写 `local_job_queue.json`（`status: needs_review` / `clean`），由 Marvis 闭环消费。

## 六、为什么"不影响正常使用"（给 Hermes 判读的完整依据）

```
调用链（运行时真正读的）：
  Windows 注册表 env: DEEPSEEK_API_KEY  ← setx 永久写入，重启仍在
        ↓ 引用（占位符，非明文）
  ~/.hermes/config.yaml   → api_key_env: CNB_TOKEN / ${DEEPSEEK_API_KEY}
  ~/.codebuddy/models.json→ apiKey: "${DEEPSEEK_API_KEY}"
  15721/15730 代理         → 读环境变量注入请求头
        ↓
  api.deepseek.com        → 正常鉴权

日志 .md（本次要清的对象）：
  对话记录/历史会话/20260803_2000_20260803.md   ← 只存档历史会话，无任何进程读取
```

**因此**：脱敏日志 .md 里的明文 = 只改"存档副本"，运行时链路完全不受影响。功能零风险。
