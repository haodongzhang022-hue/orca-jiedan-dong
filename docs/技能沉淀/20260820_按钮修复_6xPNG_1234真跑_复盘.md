## 二、按钮 bug 的真根因（避免复发）

```
【症状】点「⚡ 一键调用 1234 执行」按钮，WorkBuddy 内嵌预览无反应
【旧实现】confirm() + alert() + Bash 命令字符串
【根因】WorkBuddy 内嵌预览 iframe 沙箱拦截了 confirm/alert/window.open 三件套
       浏览器物理上无法 exec BAT（沙箱隔离）
【修复方案】
  1) 自绘 HTML/CSS/JS modal（position:fixed + z-index:99999）零拦截
  2) 加 console.log + 按钮颜色翻转 + 文字反馈 → 多重信号
  3) 加 document.addEventListener click delegation 兜底
  4) "模拟执行"按钮 → 4 阶段计时器 + 实时 log + localStorage 计数
```

**预防规则**：
- 在 WorkBuddy 内嵌 HTML **永不**用 `confirm()/alert()/prompt()` 或 `window.open()`
- 一律改 `position:fixed` 自绘 modal
- 涉及调用 BAT 必须给 3 种 fallback（双击/PowerShell/Bash）

## 三、SVG 模糊的真根因

```
【症状】WorkBuddy 面板以 230% 缩放显示 SVG（缩放≠精度）
【根因】SVG 是矢量的没错，但 WorkBuddy 在小窗口（<1440px）内显示时
       把 SVG 当图片缩放，且 SVG 内嵌了 1440×1320 坐标系的文字字号偏小
【修复方案】
  1) Edge headless --force-device-scale-factor=6 --window-size=1440,1320
     → 输出 8640×7920 真 6× 矢量精度 PNG (4.6MB)
  2) 工作台内 openSVG6x() 自绘 modal 直接展示该 PNG
  3) 路径: assets/diagram/agency_agents_国际对标_6x.png
```
