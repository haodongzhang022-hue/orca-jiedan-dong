## 二、ModLens 升级为多后端（v1.0.0 → v1.1.0）

`deepseek-harness/plugins/modlens/modlens.py` 重写为 `backend: auto` 多后端：

```
auto 探测顺序：gemini(有 key) → ollama(端口可达) → tesseract(有可执行文件)
任一后端失败自动逐级降级，最终 Pillow 元数据兜底，不阻断链路
```

- `settings.yaml`：`backend: auto` + `ollama_url` / `ollama_model` / `ocr_lang` 可配置。
- 新增 `--status` 查看三后端就绪状态。
- 新增一键验证脚本 `tests/verify_modlens_vision.py`。

## 三、tesseract OCR 预处理（关键踩坑，显著提效）

实测发现：**放大（upscale）是中文 OCR 质量的决定性因素**，单纯灰度/对比度/Psm 6 效果有限。

- 原始 tesseract：输出乱码「Q BR + 园 i&if …」
- 加 3x 放大 + 灰度 + autocontrast + Psm 6：稳定识别「平面设计【新人接单@群】【满20单】可申请升级，详看群公告」「注意>私加客户，开除不结算」等人名/电话/规则。

落进 `ModLens._preprocess_for_ocr()`：目标宽 ~3000px，至少 2x、封顶 4x 放大。

## 四、踩坑沉淀（防复发）

1. **第三方 API Key 申请不可由 Agent 代办**：需用户本人账号 OAuth，Agent 只能做到「预留好配置 + 一键验证」，不能替用户登录/建号。
2. **Ollama「端口可达」≠「能推理」**：`/api/tags` 返回 200 不代表能跑模型，`llama-server.exe` 缺失时 `/api/chat` 才 500。自动探测要区分「服务在线」与「推理可用」。
3. **OCR 先放大再识别**：小图/手机截图直接 OCR 基本废，3x 放大是中文 OCR 的前提。
