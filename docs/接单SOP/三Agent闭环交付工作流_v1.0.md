# 🦞 三Agent闭环交付工作流 v1.0

> 适用：企业微信群定制接单项目 · 设计类商单
> 原则：**订单完成 = 成果文件落盘 + 客户验收 + 二次修改闭环，直到交付使用**
> 成本：零成本（全本地 · 零积分 · 零网络）

---

## 一、三Agent角色定义（闭环核心）

| 角色 | Agent | 职责 | 输入 | 输出 |
|------|-------|------|------|------|
| 🧠 大脑 | **Hermes** | 接单 → 建档任务卡 → 研判报价 → 点名分配 → 客户沟通 | 群消息/客户对话 | 任务卡.md + 报价话术 |
| ⚙️ 执行 | **codex** | 按任务卡待办出成果文件（PSD/AI/PDF/JPG/网页） | 任务卡 + 参考 | 最终交付文件 + 工程源文件 |
| 🔍 审核 | **Claude Code** | 硬校验（尺寸/出血/版权/错别字）→ 写 review_report → 放行/打回 | 成果文件 | review_report.md + 放行结论 |

> 闭环不结束于「审核放行」，而结束于「**客户交付使用 + 二次修改闭环完成**」。

---

## 二、闭环状态机（5 状态）

```
已接单(Hermes建档)
   ↓
执行中(codex出稿)
   ↓
待审核(Claude Code校验)
   ↓
已放行(审核通过)
   ↓
已交付(客户确认使用)
   ↑___________________ 客户提二次修改意见 ↩ 回退到「执行中」
```

**回退规则**：只要客户有修改意见，状态机立即回退到「执行中(codex改)」，codex 改稿 → 再「待审核」→ Claude Code 重审 → 再「已放行」→ 客户再验收。循环直到客户无意见 = 真正交付使用。

---

## 三、标准交付物（每单必出 5 件 + 3 文档）

### 5 件交付物（工作台一键交付生成）
1. 订单概况
2. 报价话术（发客户）
3. 交付话术（发客户）
4. 复盘模板
5. SKILL 增量（沉淀）

### 3 份落盘文档（gen_deliverables.py 真落盘）
1. `任务卡.md` — Hermes 建，五段结构 + 状态机头部
2. `review_report.md` — Claude Code 写，硬校验 + 结论
3. `客户验收单.md` — 含二次修改记录表（闭环核心）

**落盘位置**：`01_正在执行实单/【日期_客户_需求】/交付/`

---

## 四、操作流程（接单 → 交付 → 闭环）

### Step 1 · 接单（Hermes 大脑）
- 企业微信群收到需求 → 粘贴到工作台「群消息实时看板」→ 一键解析入池
- 选中订单 → 点「⚡ 一键交付」生成 5 件交付物
- 点「📦 导出交付清单 JSON」→ 落盘前的数据包

### Step 2 · 执行（codex）
- codex 按任务卡出成果文件（源文件/PDF/JPG）
- 成果文件放 `01_正在执行实单/{目录}/最终交付文件/`

### Step 3 · 审核（Claude Code）
- Claude Code 硬校验 → 写 `review_report.md`
- 结论「已放行」或「打回」

### Step 4 · 落盘（一键）
- 把「交付清单 JSON」放到 `scripts/` → 运行：
  ```bat
  python scripts/gen_deliverables.py 交付清单_{订单名}.json
  ```
- 自动写到 `01_正在执行实单/{目录}/交付/` 下 5 个文件

### Step 5 · 二次修改闭环（客户验收）
- 客户提意见 → 在工作台「闭环看板」填入「客户意见」→ 点「回灌闭环」
- 状态机回退「执行中(codex改)」→ codex 改 → Claude Code 重审 → 再放行
- 循环直至「已交付使用」

## 六、防复发约束

1. **不可只生成预览不落盘**：交付清单 JSON 必须过 gen_deliverables.py 真正写文件
2. **不可跳过二次修改**：客户有意见必须回灌，状态机回退，否则不算交付
3. **不可混淆三Agent**：Hermes=大脑/codex=执行/Claude Code=审核，角色不串
4. **闭环终点是交付使用**：不是审核放行，是客户真正用上 + 无修改意见

## 七、与龙虾五步法 + 全域模板对齐

- Step1 识别 → Hermes 接单研判
- Step2 映射 → 任务卡五段映射交付物
- Step3 规划 → 三Agent分工 + 状态机
- Step4 执行 → codex 出稿 + Claude Code 审核
- Step5 沉淀 → SKILL 增量 + Obsidian + 调用1234

四化校准：
- 智能化：Hermes/codex/Claude Code 自主闭环，不问用户
- 定制化：每单蒸馏客户微画像 + 修改意见
- 全自动化：一键1234 + gen_deliverables 全自动落盘
- 自我净化：每单沉淀 5 件 + SKILL 增量，优化脚手架
