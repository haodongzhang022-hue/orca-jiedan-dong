# 🔀 我方 vs CNB vs 联手（生产模式对比与决策）

> 当前架构决策 / 三模式优缺点 / 何时切到联手
> 适用：所有想用 CNB 同步 + WorkBuddy 本地执行的场景
> 版本：v2.0 · 2026-08-20

---

## 一、三模式定位（一句话版）

| 模式 | 一句话 | 本质 |
|---|---|---|
| 📍 **我方** | WorkBuddy 本地 + Ollama + MiMo | 零延迟·零成本·纯研发 |
| ☁️ **CNB** | CNB 云端免费仓库 + CI/CD | 7×24·多端·跨账号 |
| 🔥 **联手** | 我（创意）+ CNB（存证）+ 双向同步 | **生产标准·双轨闭环** |

**最终结论**：联手 = 生产模式。无需二选一，**只需要选怎么联手**。

## 二、五维优缺点对比（详细）

### 1. 算力

| 维度 | 我方 | CNB | 联手 |
|---|---|---|---|
| 提供方 | Ollama/MiMo 本地 | 5GB 仓库额度 | 互补 |
| 限制 | 关机即停 | 超出额度付费 | 主备互补 |
| 适合 | 重写模型推理 | 静态文件 | 商单生产 |
| 成本 | 0 元 | 0 元（免费层） | 0 元 |

### 2. 鉴权

| 维度 | 我方 | CNB | 联手 |
|---|---|---|---|
| 入口 | BAT 双击 | GitHub PAT | 本地生密钥 + CNB 推 |
| 复杂度 | 低 | 中（PAT 轮换） | 中 |
| 风险 | 弱（仅本机） | 中（凭证泄露） | 双因子 |
| 推荐 | 单机调试 | 团队协作 | 全场景 |

### 3. 速度

| 维度 | 我方 | CNB | 联手 |
|---|---|---|---|
| 调用延迟 | < 100ms（本地） | pull/push 30s+ | 本地优先 |
| 冷启动 | 0（已运行） | 5-10s | 主备切换 |
| 网络依赖 | 0 | 100% | 仅 CNB 同步阶段 |
| 推荐 | 实时交互 | 批量任务 | 双轨缓冲 |

### 4. 稳定性

| 维度 | 我方 | CNB | 联手 |
|---|---|---|---|
| 在线率 | 视本机 | 99.5%（云） | 主备互补 |
| 数据安全 | 本地+外置硬盘 | 异地容灾 | 双重保险 |
| 故障恢复 | 重启+恢复 | CNB 自动 | 主备切换 |
| 适合 | 个人/小团队 | 中小团队 | 全场景 |

### 5. 商业化能力

| 维度 | 我方 | CNB | 联手 |
|---|---|---|---|
| 客户凭证 | 无 | URL 即可访问 | **双重凭证** |
| 跨账号 | 难 | 易 | 易 |
| 监管/法务 | 弱 | 中（云端存证） | **强（双方存证）** |
| 收入 | 商单（高） | SaaS（中） | **商单+SaaS（最高）** |

## 三、何时切换（决策表）

```
当前状态                →  切换到
──────────────────────────────────────
单机调试 / 纯研发     →  📍 我方
团队协作 / 客户要凭证 →  🔥 联手
SaaS 化 / 多账号管理 →  ☁️ CNB（生产环境）
交付存证 / 跨端访问   →  🔥 联手
6+ 单并发              →  🔥 联手（防丢单）
```

**核心原则**：商单 ≤ 5 单（开发期）→ 纯本地 | 商单 6+ 单 / 客户凭证需求 → 联手

## 四、联手的标准流水线（生产模式）

```
[1] WorkBuddy 接单（本地·Ollama 推理·0 延迟）
       ↓
[2] 本地生产（设计·文案·0 工具成本）
       ↓
[3] 客户端交付（上传 CNB 仓库 → 给客户 URL）
       ↓
[4] CNB 存证（带 SHA + commit + 时间戳）
       ↓
[5] WorkBuddy 沉淀到 SKILL + Obsidian
       ↓
[6] 调用 1234 [4] 四化迭代 → wiki
```

**关键节点**：第 [3] 步上传 CNB 是唯一网络动作，单次 5-30 秒，商单成品 + 凭证双重落地。

## 五、CNB 同步脚本（已就绪）

**入口**：`scripts\cnb_sync_artifacts_free.cmd`

执行逻辑：
1. 检查 CNB 凭证（`git -c http.proxy=` 绕过系统代理）
2. 选择子项目路径：`本项目` / `其他项目` / `全部同步`
3. 备份 `.workbuddy/artifacts/*.html` + `docs/接单SOP/*.md`
4. git add + commit + push to CNB 公共仓库
5. 打印同步日志到 `logs/cnb_sync_YYYYMMDD.log`

**触发场景**：
- 一键 1234 阶段 [4] 自我净化（迭代后）
- 跨账号协作（接单人不在主机器）
- 客户要凭证（CNB URL 直接给）

## 六、P0 兜底（不要踩的坑）

| 现象 | 兜底动作 |
|---|---|
| CNB push 401 错误 | 检查 `git -c http.proxy= --no-pager` 绕系统代理 |
| CNB push 超时 30s | 切到 `git -c http.proxy= push direct` 直推 |
| CNB 凭证泄漏 | 立即去 CNB 控制台 revoke + 重生 |
| 本地 BAT 启动慢 | 检查 `fleet_guardian.py` 是否在跑 |
| 联手时本地数据未同步 CNB | 强制调用 `bash scripts/cnb_sync_artifacts_free.cmd` |
