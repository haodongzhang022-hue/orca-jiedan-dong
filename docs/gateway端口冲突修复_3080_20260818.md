# Gateway 端口冲突修复记录（3080 被 DeepSeek-Harness 占用）

> 日期：2026-08-18 ｜ 分类：运维故障排查 ｜ 状态：已修复
> 场景：本机 Windows 运行 `dsh web` + `start_gateway_3080.bat` 网关

---

## 一、现象

```bash
curl http://127.0.0.1:3080/health
```

返回的是 **HTML 网页**（`window._DSH_BOOT`），不是网关 JSON。

报错：
```
http://127.0.0.1:3080/v1/models did not answer with JSON
```

## 二、根因

**端口冲突**：

- DeepSeek-Harness（`dsh web`）**默认就监听 3080**，它跑的是 WebUI（HTML 网页后台）；
- `gateway_3080.py` 中转网关也默认想用 **3080**；
- 两个程序抢同一个端口 → 网关启动失败，端口被 Harness 占住 → curl 拿到的是网页而非 JSON。

> 佐证：`window._DSH_BOOT` 是 DeepSeek-Harness 前端注入的全局变量，说明 3080 上跑的是 Harness 网页本身。

## 三、解决方案（采用方案1：改网关端口，不动 Harness）

### 端口分工（核心）

| 端口 | 归属 | 说明 |
|---|---|---|
| **3080** | DeepSeek-Harness `dsh web` WebUI | 浏览器访问 `http://127.0.0.1:3080` |
| **3081** | `gateway_3080.py` 中转网关 | 统一代理 CNB 免费模型，`http://127.0.0.1:3081/v1` |

### 改动点

| 文件 | 改动 |
|---|---|
| `scripts/start_gateway_3080.bat` | `--port 3080` → `--port 3081` |
| `deploy/dsh-desktop/gateway_3080.py` | 默认 `GW_PORT` 3080 → 3081（含文档注释） |
| `deepseek-harness/plugins/gateway_3080/gateway_3080.py` | 与上同步 |
| `deploy/dsh-desktop/entrypoint.sh` | `GW_PORT` 默认 3080 → 3081 |
| `deepseek-harness/harness_mcp_loader.py` | `gw_http_port` 默认 3080 → 3081 |
| `deepseek-harness/config/harness_mcp_registry.json` | `start_cmd_http` / title / desc → 3081 |
| `scripts/install_mcp_plugin.sh` | base_url 示例 → 3081 |
| `docs/GW3080可视化指南.md` | 各工具 base_url → 3081 |

## 四、修复后验证

```bash
# 网关（应返回 JSON，不是 HTML）
curl http://127.0.0.1:3081/health
curl http://127.0.0.1:3081/v1/models
```

正常应返回：
```json
{"ok": true, "mode": "outbound", "model": "deepseek-v4-flash", ...}
```

## 五、DeepSeek-Harness 新增提供方配置

在 Harness WebUI（`http://127.0.0.1:3080`）新增自定义提供方：

| 配置项 | 填写值 |
|---|---|
| Provider ID | `cnb-gateway-local` |
| 显示名称 | `CNB本地网关(DeepSeekV4+GLM5.2)` |
| API 地址 | `http://127.0.0.1:3081/v1` 👉 端口是 3081 |
| API 协议 | `openai-completions` |
| API 密钥 | `local`（占位） |
| 模型 | `deepseek-v4-flash`、`z-ai/glm-5.2` |

> ⚠️ 操作顺序：弹窗里**不要点"获取可用模型"**，直接右下角【创建提供方】保存；保存完回到列表页再点"获取可用模型"。
> Provider ID 红色提示是实时校验，直接忽略弹窗提示，ID 是合法的。

## 七、操作步骤速查（本机 Windows）

1. **关闭旧进程**：关闭 dsh 网页终端、关闭旧的 gateway 黑窗口（或 `taskkill /f /im python.exe`）。
2. **启动网关**：双击 `scripts/start_gateway_3080.bat`（现在监听 3081）。
3. **验证**：`curl http://127.0.0.1:3081/health` 返回 JSON。
4. **Harness 配置**：浏览器打开 `127.0.0.1:3080`（Harness 不变），新建提供方，API 地址写 `http://127.0.0.1:3081/v1`，直接创建保存。

## 八、备选方案（方案2，不推荐）

改 Harness 启动端口，网关继续用 3080：

```bash
npx @deepseek-ai/dsh web --port 3088
```

浏览器访问 `http://127.0.0.1:3088`。需要改 npx 命令，且每次启动都要带 `--port`，不如方案1省心。
