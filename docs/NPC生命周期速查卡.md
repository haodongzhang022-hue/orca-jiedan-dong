# NPC 生命周期速查卡

> 归属：orca-jiedan 舰队 · CodeBuddy（B）出品
> 版本：v1.0 ｜ 适用范围：CNB 平台自定义 NPC（CodeBuddy / claude-code / codex / hermes / lobster）
> 定位：**触发 → 执行 → 销毁**全链路 + 各环节时间限制，一卡查全，不再翻文档。
> 数据来源：CNB 官方文档（NPC 事件 / 工作区回收 / 计费 / npc:go 参数）+ 本仓库 `.cnb.yml`、`.ci/*.yml`、`docs/Hermes_Studio_可行性拆解分析_v1.0.md`。

---

## 0. 一句话总览

```
@NPC（评论）→ 触发事件 → 拉容器/镜像 → Agent 干活 → 评论回写 → 容器销毁（一次性）
   触发限      │ 执行限                     │ 产出落库      │
  100条/1次    │ maxTurns / 20h 构建超时   │（PR/制品）     │ 无驻留
               └ 云原生开发另有 10min/18h/凌晨回收 ┘
```

- **NPC 是"一次性事件执行单元"，不是常驻服务**——每次 `@` 拉起一个全新容器，任务结束即销毁。
- 所有时间限制汇总见下表，细节见各小节。

## 1. 触发（Trigger）

| 事件 | 触发方式 | 执行分支 |
|------|----------|----------|
| `issue.comment@npc` | Issue 描述或评论中 `@NPC` | 仓库**默认分支**最新 Commit |
| `pull_request.comment@npc` | PR 描述、评审、评审评论、评论中 `@NPC` | PR **目标分支**最新 Commit；跨仓 Fork PR 若触发者为 PR 提交者则用源仓库源分支 |

### 触发限制（⚠️ 硬性）

| 限制项 | 数值 | 后果 |
|--------|------|------|
| 单次最多触发 NPC 事件 | **10 个** | 超过不触发 |
| Issue/PR 评论数上限 | **>100 条** | `issue.comment` / `pull_request.comment` 及 `@npc` 事件**均不再触发** |
| 编辑描述/评论、重开 Issue/PR | — | **不会**重新触发 NPC 事件 |
| `@` 写在引用/代码块/折叠块/列表/表格/部分 HTML 标签中 | — | **不触发**（会被当纯文本） |

### 触发身份与权限

- NPC 事件在**当前 Issue/PR 所属仓库**（非 NPC 所属仓库）下执行，触发者=当前操作者。
- 自定义 NPC 回复评论时，提交者显示为 NPC 角色名。
- `CNB_TOKEN` 仅限访问**当前仓库**；跨仓 Fork PR 且触发者为 PR 提交者时仅限**公开仓库**。
- `CNB_TOKEN` 最大角色 = 触发用户在仓库中的角色（Developer/Master/Owner → Developer；Reporter/Guest → Reporter，且**无法启用工作模式**）。
- **工作模式（替我上班）**：需仓库 Developer 及以上权限，勾选后 NPC 才可自主写代码/推分支/建 PR。

## 2. 执行（Execute）

### 2.1 执行环境（双路径）

| 路径 | 适用角色 | 镜像 | 说明 |
|------|----------|------|------|
| A（默认兜底） | lobster 等未单独配置角色 | `cnbcool/default-npc:latest` | 轻量 npc:go，开箱即用 |
| B（自定义镜像容器） | claude-code / codex / hermes | `orca-jiedan:1.6.0`（制品库镜像） | 完整原版 CLI + 适配层 + 额度监控，不蒸馏 |

### 2.2 npc:go 执行参数（本仓库实际配置）

| 参数 | 路径A（$ 兜底） | 路径B（三角色） | 说明 |
|------|----------------|-----------------|------|
| `model` | `deepseek-v4-flash` | `deepseek-v4-flash` | ⭐ 强制锁定 CNB 内置免费基座 |
| `maxTurns` | 12 | **100** | Agent 最大对话轮次，达到上限**被中止**，输出可能不完整 |
| `contextWindow` | `128k` | `128k` | 与模型对齐；超限自动摘要压缩 |

> ⚠️ **maxTurns 实战经验**（本仓库踩坑记录）：
> - 曾因 24 轮触发 `Agent aborted: reached maxTurns limit`，跨仓库编排 60 轮仍不够（构建 `cnb-p0o-1jvgj2pvt` 实证），最终三角色统一上调到 **100**。
> - 单仓轻任务 12 轮（路径A）够用；跨仓库编排/合并 PR→等构建→逐仓验收 类任务请确保走路径B（100 轮）。

### 2.3 执行期时间限制（超时/回收）

| 环境 | 时间限制 | 后果 |
|------|----------|------|
| **云原生构建流水线**（含 NPC 事件） | 最长运行 **20 小时** | 超时自动销毁 |
| **云原生开发工作区**（`vscode` 事件/WebIDE） | 见下方回收机制 | — |
| └ 心跳检测 | 创建后 **10 分钟**未进 VSCode 页面，或关闭页面后 **10 分钟**无操作 | 自动回收 |
| └ 最大保持 | 持续心跳最长 **18 小时** | 到点回收 |
| └ 不过夜机制 | 使用超 **8 小时** 且处于**凌晨 4:00–6:00** | 强制回收 |
| 镜像构建（main.push） | 构建约 **0.8 核时/次** | 计入免费配额，非时间限制 |

### 2.5 执行期的网络/鉴权限制（影响能否跑完）

| 限制 | 说明 |
|------|------|
| NPC 事件容器 | 网络出口开放（可拉包），**入站端口不开放** |
| 云原生开发容器 | 支持端口映射/转发，但服务必须监听 `0.0.0.0`（`127.0.0.1` 无法映射） |
| CNB Token | NPC 事件仅限当前仓库；跨仓操作需拆到各仓各自 NPC 事件或 `imports` 密钥仓库 |
| 密钥注入 | 仅限受信仓库/白名单（`use_in_slugs`）；量化等敏感仓不放云端密钥 |
| 适配层端口 | `127.0.0.1:8787` 仅容器内；云原生开发环境需改绑 `0.0.0.0` 才能走 WebIDE 端口映射 |

## 4. 销毁（Destroy / 回收）

| 场景 | 回收行为 |
|------|----------|
| NPC 事件容器（一次性） | 任务执行完**立即销毁**，无驻留；下次 `@` 重新拉起全新容器 |
| 云原生开发工作区 | 满足任一回收条件即销毁：①10 分钟无操作/未进页面 ②18 小时上限 ③超 8 小时且在凌晨 4–6 点 |
| 云原生构建流水线 | 超过 20 小时超时自动销毁 |
| 工作区数据 | 销毁时自动备份未提交代码（stash/未 push commit/工作区修改），重建时自动恢复；IDE 配置等文件跨环境漫游 |

## 7. 常见坑 & 规避（FAQ）

| 坑 | 现象 | 规避 |
|----|------|------|
| maxTurns 截断 | `Agent aborted: reached maxTurns limit` | 走路径B（100 轮）；跨仓库编排尤其注意 |
| 评论>100 条 | `@NPC` 无反应 | 提前归档/新建 Issue，别在超长 Issue 里继续 `@` |
| 云开发环境回收 | 长会话中断 | 关键任务用 NPC 一次性容器（执行完即交付）；云 IDE 仅做短时可视化 |
| 凌晨强制回收 | 跑了一天的环境 4-6 点没了 | 重要工作提前提交/推送，利用自动备份恢复 |
| Token 跨仓 403 | 跨仓库操作被拒 | 拆到各仓各自 NPC 事件，或用 `imports` 密钥仓库 |
| 端口映射不生效 | 公网访问不到 | 服务必须监听 `0.0.0.0`，不能绑 `127.0.0.1` |
| 额度耗尽 | AI 能力不可用 | 看 `quota_monitor.py` 告警；月底清零后次月自动恢复 |
