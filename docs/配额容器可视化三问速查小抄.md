## 问②：一个对话框 = 一个容器吗？容器在哪看？

### 一句话
> **不是。** 对话框=会话，容器=每次 `@NPC` 临时拉起的一次性运行环境，**用完即焚**。

### 三层关系（别混）

```
页面里的「对话框」 = 一个 Issue/PR 对话流
        ↓ 不等于
云端「容器」 = 每次 @NPC 触发才拉起的临时环境
        ↓ 也不等于
「构建(build)」 = 每次触发产生的一条流水线记录（有独立 sn 构建号）
```

- 同一个对话框可以触发 **N 次** NPC → 每次都是一个新容器、新构建号
- 例：Issue #27 一个对话框里已触发多次构建（`cnb-ib8...`、`cnb-bsg...` 等），每次都是独立一次性容器

### 容器在哪看？

| 看什么 | 入口 |
|--------|------|
| 每次 @NPC 的记录 | 仓库页左侧 **「构建」→ 构建列表**（或 `.../-/build/logs/<sn>`） |
| 单条构建干了多久 / 核时 / AI 用量 | 构建详情（状态、duration、prompt/completion tokens、milli_credit） |

### NPC 容器生命周期（速记）

```
@NPC → 触发 → 拉一次性容器 → 干活 → 回写评论 → 容器销毁（无驻留）
   │ 限制：评论≤100条、单次≤10个NPC事件、编辑/重开不触发
   │ 执行：构建最长20h；开发环境 10min 无操作 / 18h 上限 / 凌晨4-6点回收
   └ 免费基座 deepseek-v4-flash 有效期至 2026-12-31
```

> 📌 角色标签/配置（claude-code/codex/hermes/lobster）**永远在 git 里**，但容器是"@一次、上岗一次、干完走人"。**标签在 ≠ 容器在。**

## 问③：不能像 Docker 一样可视化吗？

### 一句话
> **能，但要走「云原生开发」按钮**（WebIDE 浏览器窗口）；NPC 一次性容器**永远没有 GUI**。

### 两条路对比

| | NPC 一次性容器（@触发） | 云原生开发环境（云上可视化） |
|---|---|---|
| 活的窗口 | ❌ 无 GUI，跑完即销毁 | ✅ WebIDE 浏览器窗口 |
| 像 Dock 看状态 | ❌ 只能看构建日志 | ✅ 文件树/终端/端口预览 |
| 生命周期 | 触发→干活→销毁 | 10min 无操作回收 / 18h 上限 / 凌晨4-6点强制回收 |
| 进入方式 | 评论区 @NPC | 仓库分支页右上角 **「云原生开发」** 按钮 |

### 本项目已经配好的可视化链路

```
点「云原生开发」按钮
  → .ide/Dockerfile 启动 Hermes Studio Web GUI（端口 6060）
  → 浏览器打开 https://{id}-6060.cnb.run
  → 云端复刻 Hermes Studio 桌面编排（出差/兜底用）
```

> ⚠️ 服务必须监听 `0.0.0.0` 才能走端口映射；云端环境**不常驻**（有回收机制），日常体验还是本地 Hermes Studio 桌面版最好。
