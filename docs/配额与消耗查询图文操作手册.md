# 配额与消耗查询图文操作手册

> 归属：orca-jiedan 舰队 · CodeBuddy（B）出品
> 版本：v1.0 ｜ 适用范围：CNB 平台（TJF19770107 组织 / orca-jiedan 仓库）
> 目的：**不用再问"我配额用了多少 / 在哪看 / 还剩多少"** —— 认准本手册三个入口 + 一张表即可。
> 数据来源：CNB 官方《定价》文档（docs.cnb.cool/zh/pricing.md）+ 本仓库实测构建记录（`cnb build get-build-*` 实查）。
> 边界：本手册不含任何密钥明文；页面入口以你本人登录后的实际界面为准（云端 NPC 只有仓库级权限，组织级数字需你本人查看）。

---

## 0. 一句话总览

```
配额 = 免费额度（每月固定，月底清零） + 超额按量计费
  ├─ 组织级总览 → 头像 → 组织 → 设置 → 用量管理     （看全组织总盘子）
  ├─ 仓库级明细 → 仓库 → 设置 → 用量统计             （看单个仓库消耗）
  └─ 制品库占用 → 制品库 → 设置 → 用量统计           （看镜像/制品占的存储）
每次 @NPC 干活 = 一条「构建记录」 → 构建列表里能点开看 AI 用量 / 核时 / 状态
```

> 💡 **当前本项目：模型全走 CNB 内置免费 DeepSeek-V4-Flash 基座（`milli_credit=0`），实测一次 NPC 干活 28 次请求 110 万 tokens，AI Credits 消耗 = 0。** 你日常基本不会超免费额度，但**开发/构建 CPU 核时**按实际使用计费，值得每月瞄一眼。

### 入口②：仓库级用量详情（看"这个仓库花了多少"）

## 2. 每次 @NPC 的消耗去哪看？（构建列表 = "账单流水"）

你之前问"容器在哪看" —— **每次 @NPC 触发都会产生一条构建记录，构建列表就是观察容器干活 + 消耗的入口**：

| 查看什么 | 路径 |
|----------|------|
| 构建列表 | 仓库页左侧 **「构建」**（或直连 `.../-/build/logs/<sn>`） |
| 单条构建状态/耗时/核时 | 构建列表每行：状态、duration、pipeline 详情 |
| 单条构建的 **AI 用量** | 构建日志页 → AI 用量/审计面板（prompt/completion tokens、milli_credit） |
| AI 请求明细（每一条模型调用） | 构建详情 → AI 请求明细（28 条逐条：时间、模型、tokens、延迟、状态码） |

**本仓库实测样本**（构建 `cnb-ib8-1jvjki7sr`，2026-08-09 那次 Issue #27 NPC 干活）：

| 指标 | 数值 |
|------|------|
| 请求次数 | 28 次 |
| prompt tokens | 1,086,581（其中缓存命中 1,028,864） |
| completion tokens | 14,315 |
| 总 tokens | 1,100,896 |
| 模型 | 全部 `deepseek-v4-flash`（CNB 内置免费基座） |
| **milli_credit** | **0**（✅ 免费，AI Credits 一分未扣） |
| 单次请求延迟 | 响应开始 1.4~2.3s，完整 2.4~19s（大输出慢） |
| 构建时长 | 约 253s（8 核 × 16G） |

> 📌 **怎么看懂"贵不贵"**：核时 = 核数 × 小时数。8 核跑 4 分钟 = 0.53 核时。免费 160（构建）+ 1600（开发）核时/月，日常接单量级根本用不完。

## 3. 免费额度速查表（官方《定价》文档核对版）

| 计费项 | 免费额度/月 | 月底清零 | 超额单价 | 统计公式 |
|--------|------------|:--------:|----------|----------|
| 仓库存储 | 100 GiB | 否（超了才计） | 1 元/GiB/月 | 日均用量 − 免费额度 |
| 对象存储 | 100 GiB | 否 | 1 元/GiB/月 | 日均用量 − 免费额度 |
| 云原生构建-CPU | 160 核时 | ✅ | 0.125 元/核时 | 月累计 − 免费额度 |
| 云原生开发-CPU | 1600 核时 | ✅ | 0.125 元/核时 | 月累计 − 免费额度 |
| 云原生构建-GPU | 0 | — | 0.5 元/核时 | 月累计 |
| 云原生开发-GPU | 0 | — | 0.5 元/核时 | 月累计 |
| AI Credits | 500 credits | ✅ | 0.05 元/credit | 月累计 − 免费额度 |

**核时换算表（8 核节点参考）**：

| CPU | 内存 | 160 核时(构建)可用 | 1600 核时(开发)可用 |
|-----|------|--------------------|---------------------|
| 8 核 | 16 GiB | 20 小时 | 200 小时 |

**关键规则**（官方原文核对）：
- 启动构建/开发后**每 5 分钟冻结一次用量** = 5 min × 节点规格；额度不足会**立即终止任务**避免超费。
- 任务**跨月执行**时用量计入**结束时间所在自然月**。
- AI Credits 覆盖：NPC、云原生开发内置 CodeBuddy、AI 代码评审等所有 AI Token 消耗。
- 超额后：AI Credits 用尽 → NPC 等 AI 能力**不可用**；CPU 用尽 → 构建/开发受限；存储超了 → 按量计费。

## 5. 常见问题（FAQ）

| 问题 | 答案 |
|------|------|
| 我到底在哪看还剩多少？ | 头像 → 组织 → 设置 → **用量管理**（你本人看；NPC 只有仓库权限拿不到组织数字） |
| 一次 @NPC 花多少钱？ | 本项目实测 **0 元**（免费基座 + AI Credits 为 0）；只消耗 CPU 核时（8核×几分钟≈0.5~1核时，免费额度内） |
| 怎么知道构建/容器在不在？ | 仓库 → **构建**列表，每次 @NPC 都有一条记录，含状态/时长/核时/AI 用量 |
| AI Credits 用完了会怎样？ | NPC 等 AI 能力不可用（官方原话："AI Credits 用尽后，NPC 等 AI 能力将不可用"），次月 1 日恢复 |
| CPU 核时用完了呢？ | 启动任务时预冻结不足 → 系统立即终止任务，不产生超额费用 |
| 怎么看是不是免费基座在跑？ | 构建 AI 用量面板：模型列 `deepseek-v4-flash` + `milli_credit: 0` |
| 每月什么时候重置？ | 自然月底清零，不叠加（存储类按日均用量，超了才计费） |
| 有脚本可以自动看吗？ | 有：`scripts/quota_monitor.py`（读构建 AI 用量→写 `.quota_state.json`→超过 95% 自动降级） |

## 6. 一键自查路径（最快路线）

```
① 看全组织总盘子：头像 → 组织 → 设置 → 用量管理
② 看本仓库消耗：orca-jiedan → 设置 → 用量统计
③ 看最近一次 NPC 账单：orca-jiedan → 构建 → 最近一条 → AI 用量
④ 确认免费基座活着：任一条构建 → 模型=deepseek-v4-flash 且 milli_credit=0
```
