## 一、三级成熟度独立定义

以下三级定义**从 CNB 云原生底层能力视角**出发，以"可量化、可实测"为准绳。每个等级给出①分数区间、②可实测验收条件、③对标参考、④业务结果。

---

### 🔷 等级一：初级（Level 1）——「链路通、能接单、需人盯」

**① 分数区间：6.0 ~ 7.9**

**② 该等级必须达成的可量化、可实测验收条件：**

| 能力维度 | 可量化验收条件（实测方法） |
|---|---|
| 安全 | ① 提交前 `bash scripts/secret_scan_precommit.sh` 零命中；② `git log --all -S "sk-"` 无明文残留；③ 全部 Token 走 `%CNB_TOKEN%`/环境变量，无 `api_key:明文` 入库 |
| 多 Agent 调度 | ① 任务卡状态机（已接单→执行中→待审核→已放行→已归档）可完整跑通一轮；② 单 Agent `maxTurns` 已绑定防失控 |
| 网关容错 | ① 免费基座 `deepseek-v4-flash` 锁定（非 pro 防扣费）；② 适配层对 429/5xx/超时**已具备指数退避重试**；③ base_url 末尾 `completions`（带 s）正确 |
| 知识库双向闭环 | ① 三份记忆卡（我的笔记/用户画像/灵魂）**存在**且随脚手架三文件版本化；② 仓库↔Obsidian **双向**同步成功，无单向断点 |
| CI/CD | ① `.cnb.yml` 双路径 A/B 可触发；② `main.push` 镜像构建/推送成功 |
| 故障自愈 | ① 任务卡在「执行中/待审核」悬挂超阈值**有看门狗自动打回/告警**；② MIMO 到期后**自动 failover 到 CNB** |
| 商单承接 | ① 至少 1 单真实商单（如夜星空01）已完整交付并归档；② 复盘已回灌 SelfLearn |

**③ 对标参考（大厂能力层级）：**
- 对标**微软 Copilot Studio 的"基础 Bot 连通"层**：能接入模型、能完成单一对话/任务链路，但**不具备跨 Agent 容错与安全红线治理**。
- 对标 **AutoGPT 早期单智能体循环**：链路通、任务可执行，但**无编排熔断、无安全基线**。
- 一句话：**能干活，但不能 7×24 无人在场地干活。**

**④ 业务结果（接单业务能做到什么）：**
- 能承接**单 Agent 可完成的轻量商单**（单张海报、单页折页、短视频封面等）。
- 交付过程**需要人盯**：任务卡可能悬挂、密钥可能泄露、GitHub 镜像可能失败，均需人工兜底。
- 产能：约 **1~2 单/日**，无法支撑并行多单。

## 三、定时对标机制设计（每 2 小时自动巡检）

### 3.1 运行位置：CNB 云端容器 vs 本地 Marvis

| 维度 | 运行层 | 说明 |
|---|---|---|
| **对标巡检任务** | **CNB 云端容器**（`.cnb.yml` 定时任务 / CI scheduled） | 对标抓取头部大厂公开 Agent 技术基线需联网、需云上访问外部技术源，且**独立性要求**决定其应在云端、脱离本地编排独立运行 |
| **差异比对 + 差距报告** | **CNB 云端容器** | 生成结构化差距报告，写入仓库 `docs/对标巡检/` |
| **差距报告写入 Obsidian** | **本地 Marvis 定时任务** | Obsidian 为本地桌面知识库，需本地 `auto_sync_30min.sh` 回流；云端生成报告→push 仓库→本地 Marvis 拉取→写入 Obsidian |
| **自动生成待办 + PR 修改清单** | **CNB 云端 NPC**（`issue.comment@npc` 触发） | 云端 NPC 读取差距报告，生成 Issue 待办 + 自动创建 PR 修改清单 |

### 3.2 权限边界（云端-本地分工）

**CNB 云端负责（只读对标 + 生成差距 + 生成待办/PR 清单）：**
- 只读抓取头部大厂公开 Agent 技术基线（微软/英伟达/字节/OpenAI 公开文档、GitHub trending、发布博客）。
- 与仓库现状做差异比对（读取仓库文档/配置，**只读**）。
- 产出差距报告（写入 `docs/对标巡检/`）并提交仓库。
- 生成结构化待办清单 + PR 修改清单（写入 Issue / 脚手架文件）。

**本地 Marvis 负责（写 Obsidian + 落地执行）：**
- 从仓库拉取差距报告，**写入 Obsidian 知识库**（本地 `auto_sync_30min.sh` 回流）。
- 对差距报告生成的待办**实际执行**（改代码、跑脚本、验证）。

> **权限边界红线**：云端对标巡检**只读仓库+外部技术源**，**不直接改生产代码/不直接写 Obsidian**；所有变更通过 PR 提交，由本地 Marvis/Hermes 执行合并与 Obsidian 归档。避免云端与本地对同一文件并发写冲突。

### 3.3 每 2 小时执行一次的实现方案

```
[CNB 云端定时] 每 2h 触发 .cnb.yml 对标巡检 job
   ├─ ① 抓取大厂 Agent 技术基线（curl 公开源，超时 30s）
   ├─ ② 读仓库 docs/ 现状 → 差异比对（结构化 diff）
   ├─ ③ 生成 docs/对标巡检/差距报告_YYYYMMDD_HH.md → git push
   └─ ④ 生成待办清单 → issue.comment@npc 触发云端 NPC → 输出 PR 修改清单并入脚手架
        ↓ push 后
[本地 Marvis 定时] auto_sync_30min.sh 拉取 → 差距报告写入 Obsidian
        ↓
[本地/Hermes] 执行差距待办 → 提交 → 下一轮对标迭代
```
