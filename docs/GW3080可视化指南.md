## 0. ⚠️ 关键边界（必读）

> **本 3080 网关是本机「出站客户端网关」，不是反向隧道，不支持外部公网接入，仅本机 127.0.0.1 访问。**

- ✅ **出站**：本机/内网工具 → `http://127.0.0.1:3080` → `gateway_3080.py` 主动 HTTPS 出站 → CNB 云原生 API → 免费 DeepSeek-V4-Flash / GLM-5.2。
- ❌ **入站**：不把本机服务「推上云端」，不做端口反向隧道，拒绝外部公网入站连接（默认仅监听 127.0.0.1）。
- 🎯 **价值**：全部算力、模型推理跑在 CNB 云端；本地工具只做前端交互，**不在本地跑大模型**，规避本地内存不足、API 限流、密钥泄露等问题。

```
本地 Hermes / Codex / Claude-Code
      │  base_url = http://127.0.0.1:3080
      ▼
gateway_3080.py（双模式插件）
      │  出站 HTTPS
      ▼
CNB 云原生 API → 免费 deepseek-v4-flash / z-ai/glm-5.2
```

## 1. 双模式架构总览

`gateway_3080.py` 已升级为**通用可安装 MCP 插件，双模式架构**，增量新增，不改动原有转发逻辑：

| 模式 | 触发方式 | 协议 | 适用工具 | 用途 |
|------|---------|------|---------|------|
| **模式一 标准 MCP** | 默认（无参数启动） | MCP stdin/stdout | Codex / Hermes-Still / DeepSeek-Harness | 作为 MCP 插件加载安装，工具式调用 |
| **模式二 HTTP 网关兼容** | `--http --port 3080` | OpenAI `/v1` 兼容 HTTP | 老工具表单填 base_url | 兼容 `base_url=http://127.0.0.1:3080` |

**两者共用同一套出站转发核心**（`stream_forward` / `non_stream_aggregate`），仅外层呈现方式不同。原有转发逻辑零改动，仅在最外层加「看门狗自愈 + 自动重试」。

### 边界与适用工具

- **模式一（MCP）**：适合原生支持 MCP 插件加载的现代工具（Codex、Hermes Studio、DeepSeek-Harness 等）。加载后暴露 `chat_completions` / `get_models` / `health` 三个工具，模型调用自动出站转发。
- **模式二（HTTP）**：适合只能填 `base_url` 表单的老工具，或脚本 `curl` 直接调用。监听 `127.0.0.1:3080`，提供 `/health`、`/v1/models`、`/v1/chat/completions`（流式+非流式自动聚合）。

> ⚠️ 两种模式都**仅本机 127.0.0.1 访问**，不支持外部公网接入；密钥一律从环境变量 `CNB_TOKEN` 读取，配置文件禁止明文密钥。

## 2. 快速开始

### 2.1 环境准备

密钥只从环境变量读取，**零明文**：

```bash
export CNB_TOKEN="你的CNB云端Token"      # 必填，出站鉴权
export CNB_AI_GATEWAY="https://api.cnb.cool/TJF19770107/orca-jiedan/-/ai/chat/completions"  # 可选，默认自动解析
export CNB_MODEL="deepseek-v4-flash"     # 可选，默认
```

### 2.2 启动模式二（HTTP 兼容，老工具用）

```bash
python3 deploy/dsh-desktop/gateway_3080.py --http --port 3080
```

验证：
```bash
curl http://127.0.0.1:3080/health
# {"ok":true,"mode":"outbound",...}
curl http://127.0.0.1:3080/v1/models
# {"object":"list","data":[{"id":"deepseek-v4-flash",...},{"id":"z-ai/glm-5.2",...}]}
```

### 2.3 启动模式一（MCP，供工具加载）

```bash
python3 deploy/dsh-desktop/gateway_3080.py
# 无参数 → 进入 MCP stdin/stdout 模式，等待宿主工具接管
```

## 3. MCP 模式完整配置 JSON（可直接复制安装）

以下 JSON 片段可直接填入各工具的 **MCP 插件列表 / servers 配置**，安装后即可经由本网关调用 CNB 云端免费模型。密钥通过 `CNB_TOKEN` 环境变量注入，**JSON 内不含任何明文密钥**。

### 3.1 通用 MCP server 配置（Claude Code / 多数 MCP 宿主）

```json
{
  "mcpServers": {
    "gateway-3080": {
      "command": "python3",
      "args": ["/绝对路径/deploy/dsh-desktop/gateway_3080.py"],
      "env": {
        "CNB_TOKEN": "你的CNB云端Token",
        "CNB_MODEL": "deepseek-v4-flash"
      }
    }
  }
}
```

> 提示：生产建议将 `CNB_TOKEN` 放在系统环境变量，JSON 内只写 `${CNB_TOKEN}` 或留空让宿主注入，避免明文落盘。

### 3.2 Codex 配置（MCP 模式）

Codex 通过 `~/.codex/config.toml` 或项目级配置加载 MCP 插件：

```toml
# ~/.codex/config.toml
[mcp_servers.gateway_3080]
command = "python3"
args = ["/绝对路径/deploy/dsh-desktop/gateway_3080.py"]
env = { CNB_TOKEN = "你的CNB云端Token", CNB_MODEL = "deepseek-v4-flash" }
```

### 3.3 Hermes Studio 配置（MCP 模式）

Hermes Studio（Hermes-Still）在其 MCP 插件列表新增一条：

```json
{
  "gateway-3080": {
    "command": "python3",
    "args": ["/绝对路径/deploy/dsh-desktop/gateway_3080.py"],
    "env": { "CNB_TOKEN": "你的CNB云端Token" }
  }
}
```

## 4. 故障排查章节：各工具指向本机 3080 网关的配置片段

本节给出 **Codex、Hermes Studio、Claude-Code 如何配置指向本机 3080 网关** 的 base_url 片段，直接复制填入各工具的 `base_url` 即可，实现全部工具经由 3080 网关去调用 CNB 云端免费 DeepSeek-V4-Flash、GLM-5.2。

> 前提：已启动 HTTP 兼容模式 `python3 gateway_3080.py --http --port 3080`，`base_url = http://127.0.0.1:3080/v1`。

### 4.1 Codex（HTTP 模式指向 3080 网关）

`~/.codex/config.toml`：

```toml
# 指向本机 3080 网关（HTTP 兼容模式）
model_provider = "cnb-3080"

[model_providers.cnb-3080]
name = "CNB 3080 网关（出站）"
base_url = "http://127.0.0.1:3080/v1"
env_key = "CNB_TOKEN"
wire_api = "responses"   # 若网关走 OpenAI 兼容，可改 "chat"
```

### 4.2 Hermes Studio（HTTP 模式指向 3080 网关）

Hermes Studio 的模型/provider 配置中，base_url 填：

```text
Provider Name:  CNB-3080 网关（本机出站）
Base URL:       http://127.0.0.1:3080/v1
API Key:        填 CNB_TOKEN（或留空走环境变量）
Models:         deepseek-v4-flash / z-ai/glm-5.2
```

### 4.3 Claude-Code（HTTP 模式指向 3080 网关）

Claude Code 通过环境变量/配置指向网关（OpenAI 兼容或 Anthropic 兼容两种，取决于网关能力；本网关为 OpenAI 兼容）：

```bash
# ~/.claude/settings.json 或启动时注入
export ANTHROPIC_BASE_URL="http://127.0.0.1:3080"      # 若走 Anthropic 兼容
export OPENAI_BASE_URL="http://127.0.0.1:3080/v1"      # 若走 OpenAI 兼容
export ANTHROPIC_AUTH_TOKEN="$CNB_TOKEN"
```

### 4.4 通用 curl 冒烟测试（任选模型）

```bash
curl -s http://127.0.0.1:3080/v1/chat/completions \
  -H "Authorization: Bearer $CNB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-v4-flash",
    "messages": [{"role":"user","content":"你好，请一句话介绍你自己"}],
    "stream": false
  }'
```

> 模型可切换：`deepseek-v4-flash`（CNB 免费主力）或 `z-ai/glm-5.2`（NVIDIA 免费层，文本/编程主力）。

### 4.5 常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| `/health` 显示 `token_present:false` | `CNB_TOKEN` 未注入 | 先 `export CNB_TOKEN=...` 再启动 |
| 429/428 报错 | CNB 免费档触顶 / NVIDIA 限流 | 切换模型或稍后重试（网关内置指数退避自动重试） |
| 出站超时 | 网络波动 | 网关看门狗自动重试（`GW_RETRY_MAX` 默认 3 次） |
| 外部连不上 | 网关仅监听 127.0.0.1（非反向隧道） | 属预期，仅本机访问，不支持公网接入 |
| MCP 宿主连不上 | 模式未切换 | 工具加载走 MCP 模式（无参数）；表单填 base_url 走 `--http` |

## 5. 健康检查与看门狗自愈

- `/health`：HTTP 模式心跳端点，返回出站模式、目标网关、Token 前缀（**仅前 12 位**，不泄全量）。
- `health` 工具：MCP 模式等价自检。
- **看门狗自愈**：出站调用异常（网络/超时/限流）自动重试，指数退避（`GW_RETRY_BACKOFF` 默认 1s，翻倍递增），最多 `GW_RETRY_MAX`（默认 3）次。
- 可调环境变量：`GW_RETRY_MAX`、`GW_RETRY_BACKOFF`、`GW_HEALTH_TIMEOUT`。
