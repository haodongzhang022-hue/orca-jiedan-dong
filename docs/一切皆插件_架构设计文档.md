# DeepSeek-Harness ·「一切皆插件」架构设计文档（增量改造·v1.0）

> 作者：Hermes（大脑层·全域模板调度）｜日期：2026-08-18｜状态：**待评审（未合入，不触发部署）**
> 触发：ISSUE #43 确认核心结论 —— **放弃 NPC 容器内部署 Docker-in-Docker，采用「镜像固化 + 进程级插件沙箱」主路径落地「一切皆插件」架构**。
> 原则：**只做增量改造，不改动已跑通的基座，不破坏 Hermes / Codex / 企微接单整套闭环。**

---

## 0. 结论先行（人话版）

1. **NPC 容器装不了 Docker**：一次性生命周期、缺内核设备，Docker-in-Docker 强行装必崩，这条路彻底放弃。
2. **不用容器嵌套也能「一切皆插件」**：
   - 镜像负责把整套基座**固化打包**；
   - 框架内部用**进程隔离当沙箱**，MCP / Hermes / Codex 全部作为插件，**配置文件控制加载卸载，基座本身不动**。
3. **端口分工要分清**：
   - NPC 不能暴露网页端口；
   - 看 Web 界面只能去 **Workspace** 调试，但 Workspace **会定时回收**，不能拿来长期跑业务；
   - 本机 3080 **不能把本地服务推上云端**；反过来，**本地起网关主动出站访问 CNB OpenAPI**，就能用上云端免费大模型。

## 1. 两套环境用途分工（NPC vs Workspace）

| 维度 | NPC（事件触发构建容器） | Workspace（调试预览） |
|------|------------------------|----------------------|
| 定位 | **生产运行载体** | **仅调试预览** |
| 生命周期 | 一次性，任务/构建/打包即销毁 | 会定时回收（10min 无操作 / 最长 18h / 凌晨 4-6 强制回收） |
| 职责 | 任务调度、CI 构建、镜像打包 | WebUI 可视化调试、模型/插件联调预览 |
| 端口 | **不做常驻 WebUI 服务，不能对外暴露端口** | 可通过代理 URL 预览 Web 界面 |
| 是否承载业务 | ✅ 是（接单/编排/交付） | ❌ 否（仅预览，回收不丢业务） |
| 数据 | 落盘持久化/镜像固化 | 临时，可随回收重建 |

> **铁律**：NPC 负责「干活的引擎」，Workspace 负责「看的界面」。二者职责分离，互不替代。

## 2. 核心架构：基座固定 + 能力热插拔

对齐 **DeepSeek-Harness 思想**：**基座固定不动，能力全部热插拔。**

```
┌─────────────────────────────────────────────────────────────┐
│                     镜像固化层（不变）                        │
│   base = harness_proxy.py + harness_agent.py                 │
│   (对话网关 + 超Agent编排，代码零修改)                         │
└─────────────────────────────────────────────────────────────┘
                          ▲ 只读引用
┌─────────────────────────────────────────────────────────────┐
│                     可插拔层（配置驱动）                      │
│  ├─ 模型层切换      → config/model_layer.json                │
│  ├─ MCP 服务注册中心 → config/harness_mcp_registry.json      │
│  ├─ 角色插件清单     → config/harness_plugins.json           │
│  │     Hermes / Codex / Claude-Code 可开关，绑定技能集        │
│  ├─ 基础技能索引     → config/harness_skills.json（原样保留） │
│  └─ 环境变量覆盖     → HARNESS_* / CNB_*                    │
└─────────────────────────────────────────────────────────────┘
```

**关键点**：可插拔层全部是「配置文件 + 环境变量」，**不修改底层代码**。加载/卸载 = 改配置 / 设环境变量 / spawn-kill 子进程。

## 4. 插件加载流程（进程级沙箱）

```
启动(NPC)
  ▼
读 harness_mcp_registry.json ── 按 spawn_kill_matrix 拉起基础服务
  │    chat_gateway / order_intake / agent_orchestrator
  ▼
读 harness_plugins.json ── 按 enabled 决定加载哪些角色插件
  │    hermes(默认开) / codex / claude_code(默认关)
  ▼
读 model_layer.json ── 绑定角色→模型 provider
  ▼
收到任务/委派
  ▼
按需 spawn 子进程（进程隔离 = 沙箱）
  ▼
任务完成 → 按 kill_policy（idle_reap / keep）回收/驻留
```

**沙箱实现**：子进程 + 受限环境（`SANDBOX_NETWORK=none`、超时、资源上限），**替代 Docker-in-Docker**。

## 5. 网络链路（关键确认）

### 5.1 不做反向隧道
- ❌ 本机 3080 的本地服务**不能**“推上云端”（无端口反向隧道，违反安全红线）。

### 5.2 采用出站网关
```
本机/内网工具 → http://127.0.0.1:3080/v1/chat/completions
      │ (gateway_3080.py 出站转发)
      ▼
CNB 官方 OpenAPI (https://api.cnb.cool/.../ai/chat/completions)
      ▼
云端免费 DeepSeek-V4-Flash
```
- 本机 3080 是**本地网关客户端**，主动出站 HTTPS 调 CNB OpenAPI，间接用上云端免费大模型。
- 密钥由环境变量注入，零明文落盘。

### 5.3 WebUI 可视化
- 仅放 **Workspace 的代理 URL** 做调试预览，**不作为正式生产服务**。

## 6. 镜像版本迭代规则

| 项 | 规则 |
|----|------|
| 命名 | `<registry>/<org>/<repo>:dsh-<desktop版本>` |
| 版本对齐 | 上游 `deepseek-harness-desktop` 的 `package.json` version（当前 2.0.x） |
| 触发 | `main.push` 自动触发 `.cnb.yml` 构建镜像 + 推送制品库 |
| 迭代 | 上游发新版 → 更新 tag → 重建推送；容器 `docker run` 用新 tag 即升级 |
| 骨架先行 | **本次 PR 只落骨架/文档，不触发部署变更**；用户确认后合入 main 才触发 `dsh-2.0.2` 构建 |
| 与现有共存 | 现有 NPC 镜像 `:1.6.0`（claude-code/codex/hermes）互不冲突，可并行 |

## 7. 风险规避清单

| 风险 | 规避措施 |
|------|---------|
| NPC 装 Docker-in-Docker 崩溃 | 彻底放弃；改用**进程级沙箱**（subprocess + 受限环境） |
| NPC 对外暴露端口 | 不做常驻 WebUI、不对外暴露端口；Web 调试仅走 Workspace |
| Workspace 定时回收 | 仅作调试预览，不作为生产载体；生产在 NPC + 镜像固化 |
| 反向隧道安全风险 | 不做本地端口推云端；改出站 HTTPS 网关 |
| 改基座破坏闭环 | 本次全部增量新增，`harness_proxy/_agent` 零改动 |
| 模型切换破坏接单 | 模型层仅配置驱动，默认 DeepSeek-V4-Flash 兜底；GLM-5.2 429 时回退 |
| 密钥泄露 | 全部环境变量注入，配置/镜像零明文 Token |
| 端口冲突 | 8080/8081/6060/3080 分工明确，不改既有端口映射 |
