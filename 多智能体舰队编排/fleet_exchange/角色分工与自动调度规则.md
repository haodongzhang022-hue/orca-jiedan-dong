## 二、自动调度规则 v2.0

### 2.1 任务生命周期

```
┌──────────┐   push   ┌──────────┐   pull   ┌──────────┐   done   ┌──────────┐
│  用户    │ ──────► │ incoming │ ──────► │  doing   │ ──────► │  done    │
│  需求    │         │  (待认领) │         │ (执行中)  │         │ (已归档)  │
└──────────┘         └──────────┘         └────┬─────┘         └──────────┘
                          ▲                      │
                          │           ┌──────────┴──────────┐
                          │           │                     │
                          │    成功   ▼               失败   ▼
                          │   ┌──────────┐        ┌──────────────┐
                          └───│ results  │        │ retry ≤3次   │
                              │ (结构化)  │        │ 或退回high优先│
                              └─────┬────┘        └──────────────┘
                                    │
                                    ▼
                            ┌──────────────┐
                            │ WorkBuddy    │
                            │ 汇总→迭代    │
                            └──────────────┘
```

### 2.2 调度规则明细

| # | 规则 | v2.0 增强 |
|---|------|----------|
| 1 | **认领**：新任务入 `incoming/` → 空闲 Agent `fleet_pull.sh auto` 自动认领最旧任务（FIFO） | auto模式无需人工触发 |
| 2 | **指定**：`to=某Agent` 的任务定向派发，跳过FIFO竞争 | fleet_push.sh 支持 to 参数 |
| 3 | **排他**：任务进入 `doing/` 即排他锁（时间戳唯一） | 天然防冲突 |
| 4 | **待命**：Agent 空闲超时（默认10min）→ 退出轮询进入低功耗待命 | 可配置超时时长 |
| 5 | **失败重试**：错误写 results/ → 留 doing/ → 上限3次 → 退回 incoming/ 标 high | 自动化全流程 |
| 6 | **视觉分流**：截图类任务由 WorkBuddy 用 Ollama 本地模型解析后再下发给 Agent | 零成本视觉管线 |

### 2.3 空闲 Agent 识别与优先分配

WorkBuddy 分发任务时的优先级矩阵：

| 任务类型 | 首选 Agent | 备选 Agent | 不分配给 |
|---------|-----------|-----------|---------|
| BASH/运维/目录操作 | Hermes | — | Codex, CC |
| 量化/MQL5/EA开发 | Codex | Hermes(BASH辅助) | CC(首轮) |
| 代码审计/风险检查 | Claude Code | — | Codex, Hermes |
| 视觉/截图/OCR解析 | WorkBuddy(Ollama本地) | Marvis(备选) | Agent们 |
| 全栈/跨域复杂任务 | Codex + CC 并行 | Hermes(BASH) | — |
