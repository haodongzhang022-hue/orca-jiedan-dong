# 龙虾判定层守卫 v1.0

> 一切「做没做成」的判定，都必须落在**结果态层**。
> 用过程信号下结论 —— 就是假成功与假失败的共同根因。

## 一、理论：判定五层信号模型

| 层 | 信号 | 可信度 | 说明 |
|---|---|---|---|
| L0 意图层 | 「我要做 X」 | ✗ | 最廉价的自欺 |
| L1 调用层 | 命令发出 / 请求已发送 | ✗ | 发出 ≠ 到达 |
| L2 传输层 | socket 通、TLS 握手成功 | ✗ | 形态 #8 / #16 |
| L3 过程层 | `rc=0` / exit code / `status` 字段 / 返回 flag | △ 弱 | **重灾区，只能当分流信号** |
| **L4 结果态** | **产物实际字节 / 数量 / hash / 内容 / 远端回查** | **✓ 唯一可信** | **判定必须落这层** |

**两条铁律**

1. **判定必须落在 L4**；L3 只用来决定「要不要继续查」，不能当结论。
2. **假成功 = L3 绿、L4 红**；**假失败 = L3 红、L4 绿**。两者同根：判定层选错。

## 二、六大反模式（静态可检出）

| ID | 名称 | 级别 | 对应形态 | 检测要点 |
|---|---|---|---|---|
| V1 | 判定复用被覆盖变量 | CRIT | #35 | 同一变量多次赋值各步 rc，最终判定只反映最后一步 |
| V2 | magic number 期望值 | WARN | #34 | 断言比较里写死字面常量，非由定义式推导 |
| V3 | 仅凭 `rc==0` 宣称成功 | HIGH | #35 近亲 | 成功分支内无任何产物检查 |
| V4 | 写产物不回读验收 | HIGH | #9 | 有写调用，之后无回读/验收调用 |
| V5 | 裸 socket 当网络判据 | HIGH | #8/#16 | 有 socket 连通，全文无应用层 HTTP 探针 |
| V6 | 退出码作唯一结论 | MID | — | 全文依赖退出码，无任何产物态校验 |

## 三、工具用法

脚本：`scripts/verdict_layer_guard.py`（纯 stdlib / 只读 / 零积分）

```bash
P0="C:/Users/Administrator/.workbuddy/binaries/python/versions/3.13.12/python.exe"

# 1 静态审计自写脚本（支持目录递归）
$P0 scripts/verdict_layer_guard.py audit scripts
$P0 scripts/verdict_layer_guard.py audit path/to/one.py

# 2 L4 结果态断言（不写死期望，按需给下界）
$P0 scripts/verdict_layer_guard.py assert --target out_v2 --ext .png --min-files 490 --min-bytes 200000
$P0 scripts/verdict_layer_guard.py assert --target report.md --min-bytes 3000 --contains "结论"
$P0 scripts/verdict_layer_guard.py assert --target pkg.zip --hash <sha256hex>

# 3 重复产物检测（推知识库后必跑：不只看「到没到」，还看「多没多」）
$P0 scripts/verdict_layer_guard.py dupcheck <dir> --ext .md

# 4 案例库 / 自测
$P0 scripts/verdict_layer_guard.py cases
$P0 scripts/verdict_layer_guard.py selftest
```

**退出码**：`audit` 有 CRIT → 1；`assert` 有未达标 → 1；`dupcheck` 发现重复 → 1；`selftest` 有失败 → 1。

## 四、V2 的正解：期望值由定义式推导

```python
# ✗ 错（形态 #34）：写死常量，产物一变就假 FAIL
if (w, h) != (948, 112): ...
if h <= 168: ...

# ✓ 对：期望值由参数推导，产物怎么变都成立
FRAME_W, FRAME_H = 16, 28
COLS, ROWS, SCALE = 14, 4, 4
EXPECT_SHEET = ((COLS * FRAME_W + COLS - 1) * SCALE, FRAME_H * ROWS)
```

## 五、实战：守卫自己连撞三次「形态 #11」（已全部修复）

> 守卫也是脚本，也会造假失败。这三轮是本技能最有价值的部分。

| 轮次 | 误报 | 根因 | 修法 |
|---|---|---|---|
| 1 | `str.replace` 被当成 `os.replace` → V4 误报 | 只按方法名 tail 匹配 | 改成**全限定名白名单** `WRITE_EXACT` |
| 2 | `os.path.exists(p)` 被当成退出码判定 → V1 误报 4 处 | 未区分变量语义 | 加 `_var_used_as_rc()`：只有 `p.returncode` / `p==0` / `if p:` 才算 |
| 3 | 两个函数里各有一个 `p` 被当成同一条 → V1 误报 2 处 | 文件级作用域 | 加 `_scope_map()`：**同作用域内**才比 |

效果：selftest 12→13→14 全绿；全量 104 文件 CRIT **6 → 2 → 0**。
**教训：守卫上线前必须先跑自己的误报收敛，否则守卫本身成为形态 #11 的制造者。**

## 八、铁律速记

1. **退出码不是真相，产物状态才是。**
2. 多步链路**逐步留证**（每步独立变量 + 立即判定），禁止复用变量。
3. 期望值**必须推导**，禁止 magic number。
4. 回查**不只看「到没到」，还看「多没多」**（防不幂等重复产物）。
5. 守卫自己也要过 `selftest`，且必须含**防误报用例**。
