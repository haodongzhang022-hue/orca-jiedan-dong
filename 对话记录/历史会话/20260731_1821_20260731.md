### 一、理论基础：Karpathy LLM Wiki 三层架构

Andrej Karpathy 提出的 LLM Wiki 方法论，核心区别于传统 RAG：

| 层级 | 说明 | 谁拥有 |
|------|------|--------|
| **Raw层（原始资料层）** | 论文、文章、播客、网页等素材 | 用户，AI只读不改 |
| **Wiki层（知识层）** | 摘要、概念页、比较分析、索引、交叉引用 | AI拥有完整所有权，用户负责阅读 |
| **Schema层（规则层）** | AGENTS.md / CLAUDE.md 配置文件 | 用户和AI共同迭代 |

**核心理念：** 资料进raw → Agent编译整理 → Wiki层沉淀 → 提问优先查wiki。知识越用越好用，而非每次从零检索。

### 四、提示词模板（万能提示词）

**1. 初始化知识库（一次性）：**
```
你现在是我的 LLM Wiki Agent。把下面这份 idea 文件原样落地，作为我完整的第二大脑，一步一步地执行，创建拥有完整规则的系统。落地过程严格参考以下 GitHub 仓库的内容：
https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f
```

**2. 资料入库（Ingest，最常用）：**
```
读取 raw/xxx.md。
基于其内容：
1. 在 wiki/ 创建对应的来源摘要页
2. 提取关键概念
3. 创建相关概念页（如需要）
4. 添加新页面与现有页面之间的交叉链接
5. 报告创建/更新了哪些文件
```

**3. 从对话采集内容到Inbox：**
```
请总结本次对话中值得长期保留的内容，包括核心结论、重要决定、可复用方法、行动项和待确认问题。排除闲聊、重复内容与敏感信息，整理成结构化 Markdown，保存到 /路径/Inbox。文件名使用日期和清晰主题，来源注明"Codex 当前对话"，暂时不要移动到 Notes 或 Projects。
```

**4. 统一整理Inbox：**
```
按照根目录 AGENTS.md 整理 Inbox 中尚未处理的资料。先检查重复内容，再拆分原子笔记，补充摘要、标签、来源和有意义的双向链接，更新相关索引。不要删除原始资料；处理后移到 Inbox/Processed。
```

**5. 向知识库提问（Query）：**
```
基于 wiki/ 中已处理的内容，回答：XXX
如有需要，补充参考 raw/ 中的资料。
```

**6. 生成MOC索引页：**
```
帮我整理所有关于 [主题] 的笔记，生成一个学习地图。
```

**7. 整理零散草稿：**
```
帮我整理「速记」文件夹里最近一周的笔记，提炼成一篇周总结。
```

**8. 检查Markdown质量：**
```
帮我检查 wiki 文件夹里的 Markdown，有没有结构或排版问题。
```

**9. 写回Q&A到wiki：**
```
把我们的"XXX"讨论整理成 wiki/ 下的一个比较页面，加上必要的链接和与现有页面的关联。
```

### 五、AGENTS.md / CLAUDE.md 规则文件模板

```markdown
# LLM Wiki Rules

## 目标
这个仓库用于维护一个可持续进化的知识系统。

## 目录约定
- raw/: 原始素材（AI只读，不修改）
- wiki/: 整理后的知识页
- AGENTS.md: Agent规则文件

## Ingest 原则
当新素材进入 raw/ 时：
1. 生成对应的来源摘要页
2. 提取关键洞察
3. 更新相关 wiki 页面
4. 添加必要的交叉链接
5. 如无现有页面则创建新页面

## Query 原则
回答问题时优先参考 wiki/ 页面；仅在必要时参考 raw/。

## 交叉引用
写新文章时，检查是否和已有文章有关联。有就在文末加 See Also。

## 工作流触发
- 触发词 "ingest"：处理新素材入库
- 触发词 "query"：基于wiki回答问题
- 触发词 "lint"：检查知识库健康状态
```

### 六、自动化流程

**完整工作流（8步跑通最小闭环）：**

```
1. 新建独立实验仓 llm-wiki-lab
2. Obsidian打开，建好 raw/ 和 wiki/ 两个文件夹
3. 仓库根目录下新建 AGENTS.md（规则文件）
4. 往 raw/ 塞第一篇文章（手动或Web Clipper）
5. Codex执行第一次 ingest（AI自动拆分、建页、加链接）
6. 回Obsidian检查wiki页面、双链、来源页
7. 基于wiki提第一个问题
8. 把好的问答继续沉淀回wiki
```

**日常持续迭代流程：**
```
看到好文章/视频/灵感
    ↓
用 Obsidian Web Clipper 保存到 raw/
    ↓
Codex 读取 → 拆分成多个Wiki页面 → 更新交叉引用
    ↓
知识关联越来越清晰 → 形成结构化第二大脑
    ↓
提问时AI优先从wiki层回答 → 知识越用越好用
```

**跨对话知识沉淀流程（Inbox方案）：**
```
多个 Codex 对话
      ↓ 保存结构化摘要
    Inbox
      ↓ 统一整理、去重、补链
Notes / Projects / Resources
      ↓
Obsidian 搜索、阅读、双向链接和知识图谱
```

### 七、关键注意事项

1. **路径确认**：Obsidian vault名称 ≠ 文件夹路径，必须在仓库管理界面确认完整路径
2. **先实验后迁移**：不要直接拿已有复杂仓库开刀，先建独立实验仓
3. **安全隔离**：密码、密钥、敏感信息不要放进vault
4. **版本管理**：大范围修改前先备份或使用Git
5. **先跑通再优化**：不要一开始就设计复杂结构
6. **核心指标**：如果wiki页面存在但没有交叉链接，你仍然只是在积累笔记而非构建知识网络
