## 解决方案

### 1. 创建fleet_guardian.py守护进程

**位置**：`E:\龙虾AI主控中心\MCP服务\fleet_guardian.py`

**功能**：
- 开机自启代理服务（15721/15730）
- 崩溃自动重启（30秒检测一次）
- 健康检查（HTTP /health端点）
- **端口冲突检测** — 自动杀死占用端口的非预期进程（如Marvis）
- 零成本运行（纯本地，不调API）
- 日志记录（崩溃/恢复事件）

### 2. 注册计划任务

```bash
schtasks /create /tn "FleetGuardian_AutoStart" /tr "python fleet_guardian.py --daemon" /sc onlogon /f
```

### 3. 集成到一键恢复

**修改**：`scripts/fleet_auto_ready.sh`

```bash
# ---- 0. 守护进程检查（核心！彻底解决反复修复）----
GUARDIAN_PY="E:/龙虾AI主控中心/MCP服务/fleet_guardian.py"
if tasklist 2>/dev/null | grep python | awk '{print $2}' | while read pid; do
    wmic process where "ProcessId=$pid" get CommandLine 2>/dev/null | grep -q "fleet_guardian"
done | grep -q "true\|yes"; then
    echo "[OK] 守护进程 fleet_guardian 运行中（自动管理15721/15730）"
else
    echo "[!] 守护进程未运行，正在启动..."
    "C:/Users/Administrator/.workbuddy/binaries/python/versions/3.13.12/python.exe" "$GUARDIAN_PY" --daemon &
    sleep 2
    echo "[OK] 守护进程已启动"
fi
```

## Codex历史根因分析

### 核心故障：Codex桌面版 401 Unauthorized

**根因链条**：
1. Codex桌面版（Codex++）默认 `wire_api="responses"`，直连MiMo API
2. MiMo API不支持Responses API格式，直接返回401
3. Codex++的管理工具会反复覆盖 `~/.codex/config.toml`，手动改了也会被还原
4. 全域模板 #287.4 当时有一条错误指导"代理端口为临时分配，应直连"，加剧了混乱

**关键突破**：
> 不对抗客户端的覆盖行为，而是让代理层适配客户端——代理 v6 同时支持 Responses API 和 Chat Completions 双格式，客户端默认配置不变也能正常工作。
